\section{Objective}

This document records the ongoing audit and hardening work for the
\texttt{gpurec} codebase.  The target is a professional-grade package with
clear module boundaries, reusable implementation pieces, consistent public
APIs, useful documentation, lightweight correctness gates, and regular
commits.  GPU-heavy validation is intentionally limited to small-tree smoke
checks during this phase because GPU memory is constrained by concurrent work.

\section{Current Baseline}

The audit resumed on branch \texttt{lean-fast-path}.  The worktree contained
tracked edits in the README, package exports, backtracking, packaging metadata,
notebooks, a HOGENOM optimization script, and one integration test.  It also
contained many untracked experiment artifacts, local datasets, AleRax checkouts,
workflow modules, CLI files, and generated outputs.  Changes in this audit are
therefore staged selectively; unrelated artifacts are not reverted.

\section{Subagent Audit Snapshot}

Three focused subagent audits were launched:

\begin{enumerate}[leftmargin=*]
  \item Core/API structure: modularity, reuse, import boundaries, and naming.
  \item Packaging/CLI/workflow: installability, entry points, and ease of use.
  \item Tests/documentation: lightweight correctness gates and documentation
        gaps.
\end{enumerate}

The first completed audit identified these high-priority findings:

\begin{itemize}[leftmargin=*]
  \item The top-level \texttt{gpurec} import exports \texttt{gpurec.workflow},
        while \texttt{gpurec/workflow/} and \texttt{gpurec/cli.py} were
        untracked.  Either those files must be committed deliberately or the
        top-level exports must be removed.
  \item \texttt{GeneReconModel} and \texttt{UniformChunkedReconModel} expose
        similar concepts with different constructor and evaluation shapes.
        Low-risk compatibility aliases would improve API homogeneity.
  \item Batch planning is duplicated between the general model and the uniform
        chunked model; the implementations have already drifted in supported
        packing strategies.
  \item Workflow and backtracking code cross module boundaries through private
        model state.  Public read-only accessors and batch-selection helpers
        would reduce coupling.
  \item \texttt{compute\_log\_likelihood} returns a negative log likelihood.
        The naming and docstring should be corrected, ideally with a
        \texttt{compute\_nll} alias and deprecation path.
\end{itemize}

The tests/documentation audit added these gate findings:

\begin{itemize}[leftmargin=*]
  \item Bare \texttt{pytest} was unsafe in this checkout because large local
        data directories lived under \texttt{tests/}.
  \item The \texttt{gpu} marker did not cover tests that skip from CUDA-aware
        fixtures rather than module-level \texttt{skipif} markers.
  \item \texttt{tests/README.md} was stale and did not document the CPU-fast
        audit gate.
  \item Some heavyweight CUDA checks were unmarked as \texttt{slow}.
\end{itemize}

The packaging/workflow audit added these findings:

\begin{itemize}[leftmargin=*]
  \item The sampling CLI relies on a Rust backtracker that is available in a
        source checkout but not guaranteed in a wheel install.
  \item Workflow rate outputs reported \texttt{pS} as
        \texttt{1 - (D+T+L)} even though the model normalizes rates through
        \texttt{log2\_softmax([0, theta\_D, theta\_L, theta\_T])}; the correct
        survival probability is \texttt{1 / (1 + D + L + T)}.
  \item \texttt{gpurec --config} accepted only JSON but failed with a raw JSON
        traceback when pointed at the visible Hydra YAML config.
  \item Checkpoints serialized paths exactly as supplied, which made sampling
        sensitive to the launch directory.
  \item Triton was listed as optional even though retained kernel modules import
        it eagerly.
\end{itemize}

\section{Implemented Increments}

\subsection{Workflow Configuration Hygiene}

The workflow configuration now normalizes and validates batch-related controls
before they are passed into \texttt{GeneReconModel}.  This makes CLI/config-file
behavior match the model's accepted vocabulary more closely and prevents
ambiguous production runs:

\begin{itemize}[leftmargin=*]
  \item \texttt{family\_chunk\_size} accepts integer-like values and common
        all-resident aliases, but rejects unsupported \texttt{auto}.
  \item \texttt{batch\_packing} aliases are normalized to
        \texttt{sequential}, \texttt{clade\_first\_fit}, or
        \texttt{depth\_first\_fit}.
  \item non-sequential packing now requires an explicit positive
        \texttt{clade\_budget}.
  \item \texttt{clade\_budget} and \texttt{max\_wave\_size} are normalized as
        positive optional integers.
\end{itemize}

\subsection{CLI Coverage}

The CLI now forwards \texttt{--refresh-preprocess-cache} through to
\texttt{RunConfig}.  Unit tests cover config round-tripping, batch-control
normalization, rejection of unsupported auto chunking, clade-budget validation,
checkpoint restore, resident-batch offset activation, XML event summaries, and
the new CLI flag.

\subsection{Repository Hygiene}

\texttt{.gitignore} now filters generated preprocessing caches, run logs,
wandb output, AleRax/local experiment directories, large local test datasets,
and generated profiling artifacts.  This keeps future status checks focused on
source, tests, and intentional documentation.

\subsection{Testing Configuration}

\texttt{pytest.ini} now excludes large data and generated-output directories
from recursive collection.  The duplicated pytest configuration in
\texttt{pyproject.toml} was removed so pytest no longer warns that it is being
ignored.  \texttt{tests/conftest.py} now auto-marks known CUDA-heavy modules as
\texttt{gpu} and selected expensive checks as \texttt{slow}.  The test README
documents the CPU-fast gate, small CUDA smoke checks, and the preferred
prebuilt-binary backtracking smoke.

\subsection{Workflow Output Correctness}

\texttt{rates\_final.tsv} and parameter diagnostics now compute \texttt{pS} as
\texttt{1 / (1 + D + L + T)}.  A unit test checks both diagnostics and the TSV
writer against this formula.

\subsection{CLI and Packaging Polish}

The CLI now rejects Hydra/YAML configs with a concise argparse error and asks
users to convert them to JSON or pass explicit flags.  JSON config parse errors
are also reported without a traceback.  \texttt{RunConfig} and \texttt{SamplingConfig} resolve
paths at construction time, so checkpoint payloads use absolute paths.  The
backtracking bridge now raises a clear error when neither
\texttt{GPUREC\_BACKTRACK\_BIN} nor the source-tree Cargo manifest is available.
Triton was moved into the required package dependencies because retained kernel
modules import it eagerly.

\subsection{API Homogeneity}

\texttt{UniformChunkedReconModel.from\_trees(...)} was added as a constructor
alias matching \texttt{GeneReconModel.from\_trees(...)}.  It explicitly accepts
only \texttt{global}/\texttt{uniform} mode because the chunked implementation is
global-only.

\subsection{Likelihood Naming}

\texttt{gpurec.core.likelihood} now exposes \texttt{compute\_nll} and
\texttt{compute\_nll\_root\_rows} as the contract-accurate names for the
negative log-likelihood helpers.  The historical
\texttt{compute\_log\_likelihood} names remain as compatibility aliases.
High-level API call sites and tests were moved to the new names.

\subsection{Model Access Boundaries}

\texttt{GeneReconModel} now exposes narrow public accessors for workflow and
export code: \texttt{family\_names}, \texttt{species\_names},
\texttt{species\_tree\_path}, \texttt{n\_families}, \texttt{family\_input()},
\texttt{activate\_family()}, \texttt{select\_batch()},
\texttt{active\_theta()}, \texttt{solver\_stat\_records()}, and
\texttt{full\_nll\_per\_family()}.  Workflow diagnostics and optimization now
use those accessors, and backtracking export uses \texttt{FamilyInput} plus
public batch activation instead of reaching through private model attributes.
A source-level unit guard checks that \texttt{gpurec/backtracking.py} and
\texttt{gpurec/workflow/*.py} no longer contain the forbidden private access
patterns.

\subsection{Reconciliation State API}

\texttt{GeneReconModel.reconciliation\_state()} now owns the solved E/Pi state
used by export paths and \texttt{pi\_matrix()}.  Backtracking now requests that
public state object instead of importing private autograd parameter extraction
or reimplementing the E/Pi solve with lower-level forward helpers.  The
source-level guard was extended to block those imports from returning to
\texttt{gpurec/backtracking.py} or \texttt{gpurec/workflow/*.py}.

\subsection{Shared Batch Planning}

Batch packing now has a shared implementation in
\texttt{gpurec.core.batch\_planning}.  \texttt{GeneReconModel},
\texttt{UniformChunkedReconModel}, and workflow configuration normalization use
the same packing vocabulary and planner.  This removes the previous duplicated
sequential and clade-first-fit logic and lets the uniform chunked API plan
\texttt{depth\_first\_fit} chunks with the same scheduling statistics as the
resident model.

\subsection{HOGENOM W\&B Launcher Curation}

The HOGENOM W\&B optimizer was split into a small compatibility wrapper and a
dedicated implementation module, with a Hydra launcher and checked-in YAML
configuration.  The model now exposes public helpers for experiment tooling:
\texttt{materialize\_batches()}, \texttt{configure\_solver\_iterations()}, and
\texttt{full\_loss\_for\_theta()}.  The curated W\&B launcher uses those public
helpers instead of importing private autograd functions or reaching into private
resident-batch state.

\subsection{Audit Notes}

Four source-like audit notes were promoted into \texttt{docs/}: AleRax
\texttt{ScaledValue} follow-up timings, core simplification candidates, the
lean-path performance regression analysis, and second-order optimization
opportunities.  Local absolute workspace paths were removed from the lean-path
note before tracking it.

\subsection{HOGENOM Helper Scripts}

The remaining source-like HOGENOM helper scripts were promoted under
\texttt{scripts/}: rate export, global/specieswise uniform optimization,
branchscale penalty reporting, KKT checking, shared optimizer helpers, and the
R tree-rate plotting utility.  The helper scripts that select resident batches
now use \texttt{select\_batch()} instead of private batch state, and the
integration resident-batch test was adjusted to use public family names.

\subsection{Notebook Cleanup}

The two remaining modified notebooks were stripped of execution counts,
outputs, and local-path output text before being kept.  Their retained changes
are source-cell edits: the Adam oscillation notebook records a deliberately
aggressive learning-rate/bounds experiment, and the reconciliation notebook now
uses memory-safe resident batches rather than rebuilding one model per chunk.

\subsection{Legacy HOGENOM Optimizer Public Surface}

The older fast HOGENOM optimizer and profiling harness were audited against
the newer model public API.  Their remaining direct access to resident-batch
internals was replaced with \texttt{select\_batch()},
\texttt{materialize\_batches()}, \texttt{solver\_stat\_records()}, and a new
model-owned \texttt{full\_genewise\_nll\_and\_grad()} helper for row-wise
optimizers.  The workflow source guard now covers these legacy scripts so
future private model imports or \texttt{model.\_} calls fail in unit tests.

\subsection{Fresh Subagent Follow-up Findings}

The latest audit slice found three high-value follow-ups: make the promoted
HOGENOM workflows discoverable from \texttt{README.md} and packaging metadata,
auto-apply the registered \texttt{unit} and \texttt{integration} pytest markers
by test path, and either restore or rename the currently hollow
specieswise-uniform GPU parity test.  The README workflow, packaging-extra,
and pytest marker items are addressed below, and the specieswise GPU test was
retitled as honest smoke/invariant coverage.

\subsection{README HOGENOM Workflow Discoverability}

\texttt{README.md} now distinguishes the installed \texttt{gpurec} CLI from
checkout-local HOGENOM experiment launchers.  It documents the curated W\&B
launcher, Hydra YAML launcher, checkpoint rate export, profiling harness,
local benchmark default paths, optional dependencies, and a one-family smoke
command that disables W\&B logging.

\subsection{HOGENOM Optional Extra}

\texttt{pyproject.toml} now exposes a \texttt{hogenom} extra for checkout-local
experiment scripts.  It groups the optional Python dependencies those scripts
import directly: \texttt{wandb}, \texttt{hydra-core}, \texttt{omegaconf},
\texttt{pandas}, \texttt{matplotlib}, and \texttt{numpy}.  The README
installation section now shows \texttt{pip install -e ".[hogenom,dev]"} for
users running those scripts.

\subsection{Pytest Marker Hygiene}

The registered \texttt{unit} and \texttt{integration} markers now correspond
to the repository layout.  \texttt{tests/conftest.py} auto-applies them for
files under \texttt{tests/unit}, \texttt{tests/integration}, and
\texttt{tests/kernels}, while keeping the existing \texttt{gpu} and
\texttt{slow} marker rules.  \texttt{tests/README.md} now documents
\texttt{pytest -m "unit and not gpu"} as the concise CPU unit gate.

\subsection{Specieswise GPU Test Hygiene}

The no-op reference/optimized environment toggles were removed from the
specieswise uniform GPU tests.  The former parity test now checks a real
forward invariant instead: the full saved-state likelihood must agree with the
root-row output mode, and the saved Pi/Pibar tensors must be present without
NaNs.  This avoids claiming optimized/reference parity where no separate
reference path is selected.

\subsection{HOGENOM Species-Name Public Surface}

The HOGENOM optimization and profiling scripts no longer call the private C++
preprocess extension just to recover species names.  They now build the model
with its default uniform origination distribution, then read
\texttt{model.species\_names} and \texttt{model.n\_species} through the public
API for output labels and exported uniform origination tables.  The workflow
source guard now blocks this private extension import from returning to the
curated HOGENOM scripts.

\subsection{Validation Note Path Hygiene}

The fresh AleRax backtracking validation notes still contained local absolute
workspace paths in reproduced command lines.  Those commands now use
repo-relative paths so the notes remain useful outside this checkout and pass
the documentation hygiene scan.

\subsection{Editor Workspace Hygiene}

Three tracked \texttt{.vscode} files were removed because they contained
developer-local interpreter, pytest, CMake, and C++ include paths.  The
repository already ignores \texttt{.vscode/}, so editor settings now remain
local instead of becoming project metadata.

\subsection{Notebook Policy Hygiene}

The tracked notebook allowlist in \texttt{.gitignore} now matches the two
notebooks that are actually kept in git.  The reconciliation notebook also no
longer embeds a developer-local repository fallback path or Conda CUDA library
path; it expects to be launched from the repository root and accepts any CUDA
13 library override through an environment variable.

\subsection{CLI Config Error Hygiene}

The CLI now reports missing JSON config files, unsupported config keys, and
missing required optimize inputs through argparse errors instead of leaking
Python exceptions.  \texttt{RunConfig.from\_dict} rejects unknown fields before
dataclass construction, so stale or misspelled JSON keys fail with a stable
message rather than a raw constructor traceback.

\subsection{CLI Batch-Control Vocabulary}

\texttt{gpurec optimize} no longer accepts \texttt{--family-chunk-size auto},
which the workflow could not execute.  The parser now accepts the workflow's
all-resident aliases and rejects \texttt{auto} before constructing
\texttt{RunConfig}, keeping CLI syntax aligned with production behavior.

\subsection{Workflow Device Default}

\texttt{RunConfig} now defaults missing devices to \texttt{cuda}.  The retained
production optimizer and sampler are CUDA-only, so an omitted device should
reach the existing CUDA-availability check instead of silently normalizing to an
unsupported CPU workflow on non-GPU hosts.

\subsection{Run Checkpoint Semantics}

\texttt{gpurec run} no longer advertises or accepts \texttt{--checkpoint} as a
sampling override.  The command now samples from the checkpoint produced by its
own optimization, while existing \texttt{run --checkpoint} invocations fail
early with guidance to use the sample subcommand for existing checkpoints or
\texttt{--resume-from}.

\subsection{README HOGENOM Path Scope}

The HOGENOM workflow README text now distinguishes the optimization launchers,
which accept explicit dataset path overrides, from the one-pass profiling
harness, which is tied to the local HOGENOM layout and exposes profiling and
batch-control flags.

\subsection{CLI Help Surface}

The production CLI now has descriptions for the main workflow, subcommands,
config/path inputs, batch controls, optimizer controls, and sampling/backtracking
flags.  The help text calls out when path inputs are required unless supplied by
\texttt{--config}, and documents the CUDA workflow default without changing
config-file merge semantics.

\subsection{Tracked Source Marker Hygiene}

The tracked C++ preprocessing sources no longer carry a stale AleRax TODO for
leaf-to-species parsing.  The comment now documents the legacy fallback and the
preferred explicit mapping path.  The clade hash constants were also renamed to
avoid false positives in lightweight secret scans.

\subsection{Documentation Map}

\texttt{docs/README.md} now gives the documentation directory an index.  It
separates current operating notes, validation notes, and historical performance
or research logs, and the main README links to that map so users do not have to
infer which notes are current guidance.

\subsection{Sampling Input Validation}

\texttt{SamplingConfig} now validates non-negative seeds and positive
\texttt{max\_events} values.  The lower-level public backtracking helpers apply
the same checks before touching a model or invoking the Rust sampler, so invalid
Python inputs fail with clear \texttt{ValueError} messages instead of reaching
unsigned Rust fields or subprocess execution.

\subsection{Install Metadata Hygiene}

The redundant \texttt{triton} extra was removed because Triton is imported
unconditionally by the retained CUDA kernels and remains a core dependency.
\texttt{numpy} moved from core dependencies into the \texttt{hogenom} extra,
where the checkout-local scripts that import it already live, and the unused
\texttt{more-itertools} dependency was removed.  The README now documents the
runtime C++/OpenMP extension-build requirement and clarifies that installed
sampling should use a prebuilt backtracking binary, while source checkouts can
fall back to Cargo.

\subsection{API Package Docstring}

\texttt{gpurec.api} now describes its actual public exports as high-level
PyTorch modules plus workflow metadata objects instead of claiming that
\texttt{GeneReconModel} is the only public symbol.

\subsection{Backtracking Event Schema}

The RecPhyloXML event-count key order is now exported once from
\texttt{gpurec.backtracking.EVENT\_KEYS}.  Workflow sampling, top-level package
exports, and the AleRax comparison script reuse that constant instead of
duplicating their own tuples.  A CPU unit test now covers the AleRax-style
\texttt{SL}/\texttt{DL}/\texttt{TL} direct-loss counting behavior.

\subsection{Backtracking Runner Helper}

\texttt{sample\_recphyloxml()} and \texttt{sample\_recphyloxmls()} now share a
single private runner for temporary JSON input creation, backtracking command
execution, and output readback.  A fake-binary unit test covers both public
sampling helpers without requiring Rust, CUDA, or a real reconciliation model.

\subsection{README Runtime Positioning}

The README now opens as stable package documentation instead of a
branch-transition note.  The supported runtime surface remains up front, while
performance-pruning history and retained benchmark context are linked through
\texttt{docs/lean-fast-path.md}.

\subsection{Sampling Runner Coverage}

\texttt{SamplingRunner.run()} now has a fast CPU unit test that stubs only
checkpoint/model loading and the Rust sampler boundary.  The test covers family
selection, deterministic seed offsets, XML and event-count file emission,
species and transfer aggregation, summary JSON output, and model cleanup.

\subsection{Workflow Model Factory}

Optimization and sampling now share a \texttt{RunConfig}-to-model factory for
AleRax family construction.  The factory keeps the common configuration mapping
in one place while leaving the workflow-specific prefetch and preprocess-refresh
choices explicit at each call site.

\subsection{Release Readiness Documentation}

The installation docs now distinguish source and development installs and call
out PyTorch/CUDA compatibility before package installation.  The README states
that HOGENOM benchmark data is local and not distributed.  The W\&B launcher
now recommends the project \texttt{hogenom} extra before a direct
\texttt{wandb} install.  A new release-readiness note records unresolved
redistribution blockers, including license selection, Rust backtracking binary
packaging, clean-checkout hygiene, and CPU-safe pre-release gates.

\subsection{Theta Initialization Validation}

\texttt{RunConfig} now rejects nonpositive D/L/T initialization rates before
workflow construction.  The public \texttt{GeneReconModel} tree and AleRax
constructors share an early theta-initialization helper, so bad API inputs fail
with clear \texttt{ValueError} messages before tree parsing or missing-file
errors can hide the issue.

\subsection{Sampling CLI Error Handling}

\texttt{gpurec sample} now reports expected user-facing failures through
\texttt{argparse} instead of printing Python tracebacks.  Invalid sampling
configuration, missing checkpoints, and workflow/runtime sampling errors are
converted into concise CLI errors.  The \texttt{run} command also no longer
keeps a dead checkpoint override branch after rejecting \texttt{--checkpoint}.

\subsection{Public API Homogeneity}

The top-level \texttt{gpurec} package now re-exports the public metadata types
returned by model helper methods.  The chunked AleRax constructor now accepts
the same \texttt{mode="global"/"uniform"} shape as the chunked tree
constructor and rejects unsupported modes before file IO.

\subsection{Family Chunk Normalization}

Family chunk-size parsing now lives in the shared batch-planning module.  The
notebook API, workflow config, and CLI parser all reuse that helper, so aliases
such as \texttt{all}/\texttt{none}/\texttt{null}, non-negative validation, and
the workflow rejection of unsupported \texttt{auto} stay aligned.

\subsection{Resume Optimizer State Reporting}

Optimization resume now records whether checkpoint optimizer state was
\texttt{restored}, \texttt{missing}, or \texttt{discarded}.  Incompatible
optimizer state is still non-fatal, but the exception text is carried into
history rows and checkpoint/summary status instead of being silently swallowed.

\subsection{CUDA-Only API and CLI Error Parity}

\texttt{GeneReconModel} now rejects non-CUDA devices during construction instead
of accepting CPU state that fails later inside the retained CUDA forward path.
Theta initialization is still validated first, so bad rates keep their specific
public \texttt{ValueError}.  The \texttt{optimize} and \texttt{run} CLI paths now
catch the same expected workflow failures as \texttt{sample}, converting normal
configuration/runtime failures into concise argparse errors without tracebacks.

\subsection{AleRax Selection Validation}

\texttt{parse\_alerax\_family\_file()} now validates \texttt{start} and
\texttt{max\_families} before opening the families file.  Invalid direct-API
selection arguments therefore produce deterministic \texttt{ValueError}
messages instead of being masked by a missing-file error or by the later empty
selection check.

\subsection{Workflow Tolerance Validation}

\texttt{RunConfig} now rejects negative solver and optimizer tolerances before
the workflow starts.  This covers E/Pi adaptive stopping, gradient-change
checks, gradient-norm stopping, loss-change stopping, and
\texttt{best\_likelihood\_min\_delta}; zero remains accepted for exacting
regression runs.

\subsection{Uniform Chunked Constructor Guardrails}

\texttt{UniformChunkedReconModel} now matches the public error ordering of the
main API more closely.  Invalid \texttt{theta\_init\_rates} are rejected before
tree or family-file IO, and unavailable CUDA devices fail with a clear runtime
message before preprocessing starts.  The AleRax constructor applies the same
early checks before parsing the families file.

\subsection{Sampling Filename Safety}

Sampling output filenames no longer trust raw AleRax family labels as path
components.  The workflow now prefixes files with the numeric family index and a
sanitized stem, while retaining the original family label in
\texttt{event\_counts.tsv} for traceability.  This prevents labels containing
path separators or parent-directory fragments from escaping
\texttt{reconciliations/all}.

\subsection{Shared API Validation Helpers}

Public model constructors now share CUDA-device and
\texttt{theta\_init\_rates} validation through \texttt{gpurec.api.\_validation}.
This removes duplicated error-ordering logic between \texttt{GeneReconModel}
and \texttt{UniformChunkedReconModel} while preserving the existing constructor
regression tests.

\subsection{Uniform Folder Selection Validation}

\texttt{UniformChunkedReconModel.from\_folder()} now validates \texttt{start}
and \texttt{max\_families} before checking for species or gene-tree files.  Bad
selection arguments therefore report deterministic user-input errors instead of
being masked by missing-file diagnostics from the folder scan.

\subsection{Safe Artifact Loading}

User-supplied optimization checkpoints and preprocessing caches now load through
PyTorch's \texttt{weights\_only=True} path.  The workflow validates checkpoint
payload shape before using it, and preprocessing cache entries are checked for
the expected dictionary keys.  The release-readiness notes now state that legacy
pickle-only checkpoints and caches should be regenerated or migrated only from a
trusted source.

\subsection{Checkpoint Version Validation}

Checkpoint loading now rejects payloads whose stored schema version does not
match the supported checkpoint version.  This turns future or incompatible
checkpoint files into explicit errors before optimization resume or sampling can
use partially compatible metadata.

\subsection{Packed Memory Policy Planning}

Automatic uniform pipeline selection now estimates resident chunk memory with
the same batch planner used to build chunks.  Non-sequential packing policies
such as \texttt{clade\_first\_fit} and \texttt{depth\_first\_fit} therefore use
the planned maximum chunk size, instead of a contiguous-window approximation
that could under-estimate memory for reordered batches.

\subsection{Memory Policy Input Validation}

The uniform memory-policy helpers now reject invalid dimensions before returning
payload estimates.  Scratch rows, clade counts, live-byte offsets, wave sizes,
species counts, and candidate policy values are checked at the helper boundary,
and policy candidate validation now happens before probing CUDA memory.
This keeps CPU-only or memory-constrained validation paths from touching CUDA
when user-supplied policy candidates are already invalid.

\subsection{Release Tooling Documentation}

Packaging documentation now distinguishes source-checkout benchmark scripts
from installed package commands.  The sampling CLI help states that installed
sampling requires a Rust backtracking binary through \texttt{--backtrack-binary}
or \texttt{GPUREC\_BACKTRACK\_BIN}, while source checkouts can still use the
locked Cargo fallback with the pinned public \texttt{rustree} git dependency.
A \texttt{release} optional dependency group records the maintainer
tooling needed for \texttt{python -m build} and \texttt{twine check}.

\subsection{Workflow Numeric Finiteness}

\texttt{RunConfig} now rejects non-finite floating-point controls before
optimization starts.  Tolerances, stopping thresholds, rate bounds,
theta-initialization rates, and optimizer learning rates are checked with
\texttt{math.isfinite()} before their range checks, so JSON or CLI values such
as \texttt{NaN} and \texttt{Infinity} cannot propagate into optimizer state,
checkpoint metadata, or stopping diagnostics.

\subsection{Shared Sampling CLI Mapping}

\texttt{gpurec sample} and \texttt{gpurec run} now build
\texttt{SamplingConfig} through a shared CLI helper.  This removes duplicated
sampling-option wiring between the direct sampling command and the
optimize-then-sample command, and a unit test pins the mapping for output
directory, sample count, seed, family selection, event limit, and backtracking
binary options.

\subsection{CPU Unit CI Gate}

The documented fast CPU gate is now represented in repository automation.
A new GitHub Actions workflow installs the package with development test
dependencies and runs the CPU unit marker expression on pushes and pull
requests.  The test README points to the workflow so local and automated
validation use the same gate.

\subsection{Optimization Runner CPU Coverage}

\texttt{OptimizationRunner.run()} now has fast CPU coverage using a small fake
PyTorch model with real gradients and optimizer state.  The test exercises the
runner loop without CUDA or tree preprocessing and checks history JSONL,
summary JSON, best/latest checkpoints, final rates, per-family likelihoods,
theta output, optimizer status, and model cleanup.

\subsection{Optimizer Checkpoint Consistency}

Adam and Adagrad workflow rows now describe the model state that is actually
saved in checkpoints.  After an ordinary optimizer step and clamp, the runner
performs one current-theta evaluation before recording history rows or writing
best/latest checkpoints.  The CPU fake-model regression now checks every saved
checkpoint row against the saved theta-derived loss, preventing pre-step metrics
from being paired with post-step weights.

\subsection{Strict AleRax Family Fields}

AleRax family-file parsing now rejects malformed assignment lines, unknown
family keys, and empty values inside family records.  This catches common input
mistakes such as misspelled \texttt{mapping} or tree keys before preprocessing,
instead of silently dropping mappings or accepting partially parsed family
metadata.

\subsection{Public Theta Initialization Finiteness}

Public model constructor helpers now reject non-finite
\texttt{theta\_init\_rates}.  \texttt{NaN} and \texttt{Infinity} values fail
with a clear \texttt{ValueError} before device validation, tree IO, or
preprocessing, matching the workflow-level numeric finiteness checks for direct
API users.

\subsection{Direct API Numeric Validation}

The direct model entry points now validate finite solver controls before
touching CUDA-backed state.  They cover iteration counts, tolerances, pruning
thresholds, solver-iteration reconfiguration, and theta clamping.  The tree and
AleRax factory helpers also preflight supplied solver kwargs before device
validation or file parsing.  The uniform chunked API applies the same early
checks for its public solver controls, including the AleRax family constructor.

\subsection{Backtracking Payload Finiteness}

Backtracking JSON payloads now reject non-finite numeric values before the Rust
sampler is launched.  Exported tensors and nested payload lists are checked
recursively, and the subprocess bridge writes JSON with non-standard
\texttt{NaN}/\texttt{Infinity} emission disabled.  The new CPU regressions cover
both a fake reconciliation state with a non-finite \texttt{pi} entry and a
hand-built subprocess payload that must fail before process launch.

\subsection{Backtracking Public Family Metadata}

Backtracking no longer re-enters private C++ preprocessing to recover clade
leaf labels.  Preprocessing now asks for the lightweight detail needed by the
sampler, drops unused heavy detail fields, stores leaf labels on each public
\texttt{FamilyInput}, and bumps the preprocess cache key so older light caches
are not reused without labels.  The public-surface guard now forbids private
preprocessing imports from returning to the workflow and backtracking bridge.

\subsection{Legacy HOGENOM Script Boundary}

The large checkout-local HOGENOM launchers are now explicitly marked as legacy
experiment reproducers rather than supported production workflow code.  The
project README and a new \texttt{scripts/README.md} point production users to
\texttt{gpurec optimize} and state that new shared workflow behavior belongs in
\texttt{gpurec.workflow} first.  A CPU unit guard checks that the two large
launchers keep their legacy module headers and remain named in the scripts
README.

\subsection{Workflow JSON and Resume Guards}

Workflow config loading now uses a strict JSON object loader shared by
\texttt{RunConfig.from\_json()} and the CLI.  Non-standard
\texttt{NaN}/\texttt{Infinity} constants and badly typed scalar JSON values fail
with field-specific, no-traceback errors.  \texttt{gpurec run} refuses to sample
when optimization returns failed, and resume now loads a checkpoint once so
\texttt{theta}/status and optimizer state cannot come from different reads.

\subsection{Batching Contract Validation}

Core batching no longer relies on Python \texttt{assert} statements for malformed
CCP helper detection.  Gene-family collation now validates split helper lengths
and split-block coverage before slicing tensors, while wave layout construction
validates helper lengths and exact clade coverage, including duplicate and
out-of-range clade IDs.  A subprocess regression exercises the malformed
collation path under \texttt{python -O} so optimized interpreters cannot bypass
these checks.

\subsection{Family Input Copy Boundary}

The public \texttt{family\_input()} accessor now returns defensive copies of
CCP helper containers and leaf-index tensors instead of references into the
model's cached preprocessing state.  The regression mutates tensors, nested
helper containers, gene-tree paths, leaf-species maps, and clade labels returned
from \texttt{FamilyInput}; the model-side dataset records remain unchanged.

\subsection{Sampling Rerun Hygiene}

Sampling runs now clear prior gpurec-generated reconciliation artifacts before
writing a new result set.  The cleanup is scoped to sample XML files,
per-sample event-count files, and aggregate report files under the sampling
output directory, leaving unrelated user files in \texttt{reconciliations/all}
untouched.  The workflow regression seeds stale generated artifacts before a
rerun and verifies that the final directory contains only current samples.

\subsection{AleRax Input Uniqueness}

AleRax family and mapping parsers now reject duplicate identifiers before any
preprocessing occurs.  Repeated family names can no longer collapse through the
dicts used for raw and cached preprocessing payloads, and duplicate gene
mapping entries can no longer use last-writer-wins semantics to silently move a
gene leaf between species.  The new parser regressions cover both duplicate
family records and duplicate cross-species gene assignments.

\subsection{Nested Preprocess Cache Validation}

Preprocess cache loading now validates nested species and family payload
structure instead of checking only top-level keys.  Species caches must include
consistent topology tensors, species labels, row maxima, and name-index maps;
family caches must include a CCP dictionary with consistent split counts,
split-helper tensor lengths, root clade bounds, clade labels, and leaf mapping
tensors.  Malformed caches now fail with cache-specific refresh guidance before
model construction reaches lower-level tensor or CUDA code.

\subsection{Release Metadata Gate}

The package metadata now declares maintainership, conservative PyPI classifiers,
and project URLs for the repository, issue tracker, and README.  A new release
metadata checker makes readiness machine-checkable: the current tree now reports
only the unresolved license blockers rather than also missing authors,
classifiers, or URLs.  The release-readiness guide documents that the check must
fail until a license file, license metadata, and matching license classifier are
chosen by the project owner.

\subsection{Packaging CI Gate}

The CPU GitHub Actions workflow now includes a packaging job in addition to the
editable-install unit gate.  The job installs the release extra, builds source
and wheel artifacts, runs \texttt{twine check}, installs the built wheel without
re-resolving already-installed runtime dependencies, and smokes
\texttt{python -m gpurec.cli --help}.  A source-level unit guard checks that the
workflow continues to contain the build, metadata-check, wheel-install, and CLI
smoke commands.

\subsection{Checked Minimal Workflow Example}

The README now points users to a minimal flat JSON workflow config under
\texttt{examples/}, backed by a tiny AleRax-style species tree, gene tree,
family file, and mapping file.  A CPU unit test loads the JSON through
\texttt{RunConfig.from\_json()} and parses the family file, giving the public
config shape a checked example without requiring CUDA or optimizer execution.

\subsection{Python Version CI Matrix}

The CPU unit workflow now runs the declared support range on Python 3.10, 3.11,
and 3.12 instead of only Python 3.10.  The PyPI classifiers and release metadata

\subsection{Rust Backtracking Clean Checkout}

\texttt{crates/gpurec-backtrack} no longer depends on an ignored local
\texttt{rustree/} checkout.  Its Cargo manifest now pins \texttt{rustree} to a

CLI help smoke.  The remaining release decision is whether public artifacts

\subsection{Rust Backtracking JSON Fixture}

\subsection{Preprocess Cache README Guidance}

The production workflow section of the README now documents

\subsection{Integral Solver Controls}

The shared public API integer validator now rejects boolean and fractional
solver controls instead of coercing them through \texttt{int(...)}.  Direct
\texttt{GeneReconModel} and \texttt{UniformChunkedReconModel} construction,
pre-IO factory validation, solver reconfiguration, and direct
\texttt{RunConfig} construction now fail with clear integer-control errors for
values such as \texttt{4.5} or \texttt{True} before CUDA setup or file parsing.

\subsection{CI and Release Documentation Alignment}

The Rust backtracking CI job now runs all tests marked
\texttt{integration and not gpu} instead of naming the current JSON fixture

\subsection{Backtracking Subprocess Error Context}

The Python backtracking bridge now captures subprocess stdout and stderr,
checks the return code explicitly, and raises a \texttt{RuntimeError} with the
command, exit code, and captured process output.  Successful Rust invocations
must also produce the expected single-sample XML file or every requested
multi-sample XML file; missing outputs are reported before the temporary
directory disappears.  Focused fake-binary regressions cover nonzero exits,
stderr/stdout propagation, and missing single or batched output files.

\subsection{AleRax Family Selection Validation}

AleRax family-window controls now normalize through a shared parser-layer
helper before any CUDA requirement or filesystem access.  The parser and both
public \texttt{from\_alerax\_families(...)} constructors reject negative,
fractional, boolean, and non-positive selection values with
\texttt{ValueError}s tied to \texttt{start} or \texttt{max\_families}, so CPU
hosts see the actionable input error instead of a masked CUDA-device failure.

\subsection{Explicit GPU Marker Policy}

GPU test intent now lives in the GPU-only modules themselves via module-level
\texttt{pytestmark = pytest.mark.gpu}.  The collection hook no longer maintains
a filename allowlist or infers GPU markers from \texttt{skipif} reason text; it
only applies directory-level \texttt{unit}/\texttt{integration} markers.  Slow
test intent lives on the expensive tests themselves.  A source-level guard
checks that CUDA-gated test modules keep module-level GPU intent, and
\texttt{tests/README.md} documents the explicit-marker policy.

\subsection{AleRax Compatibility Flag Guard}

\texttt{GPUREC\_ALERAX\_COMPAT} is now rejected by a shared public-API guard
before model constructors perform CUDA checks or input-file parsing.  Direct
resident construction, resident factories, and uniform/chunked factories all
raise a clear \texttt{RuntimeError} that names the unsupported environment
variable and tells users to unset it or set it to \texttt{0}.  Forward/autograd
paths retain the same guard so late environment changes fail with the same
message instead of a delayed \texttt{NotImplementedError}.

\subsection{Core Runtime Invariants}

The remaining production \texttt{assert} in the adaptive Pi convergence path
was replaced with an explicit \texttt{RuntimeError} invariant.  The
optimized-Python source guard now covers both \texttt{gpurec/core/batching.py}
and \texttt{gpurec/core/forward.py}, so core validation failures keep their
runtime checks when Python is launched with \texttt{-O}.

\subsection{Script Runtime Invariants}

The checkout-local HOGENOM profiling script no longer relies on a production
\texttt{assert} to ensure that active-batch profiling has selected a resident
batch.  The invariant now raises an explicit \texttt{RuntimeError}, and a
source guard covers all Python scripts under \texttt{scripts/} so optimized
interpreters cannot silently remove retained script checks.

\subsection{CLI Failed Optimization Exit Status}

\texttt{gpurec optimize} now exits nonzero when the workflow returns an
\texttt{OptimizationResult} with \texttt{status="failed"}.  The command still
prints its status summary to stdout, but scripts and CI no longer see a
successful process exit for failed optimization runs.  A focused CLI regression
keeps the existing no-traceback behavior and confirms \texttt{gpurec run}
continues to refuse sampling after failed optimization.

\subsection{Backtracking Comparison Rate Parsing}

The legacy \texttt{compare\_backtracking\_alerax\_events.py} diagnostic now
validates AleRax rate files before indexing into them.  Family-specific
\texttt{*\_rates.txt} files and global \texttt{model\_parameters.txt} files are
read with explicit UTF-8 decoding, checked for a header plus data row, checked
for the expected D/L/T columns, and non-numeric rates are reported as
path-rich \texttt{ValueError}s instead of raw \texttt{IndexError}s.

\subsection{Installed Console Script Release Smoke}

The package CI job and release checklist now smoke the installed
\texttt{gpurec --help} console script after installing the built wheel, in
addition to \texttt{python -m gpurec.cli --help}.  The metadata unit guard
requires both commands so future workflow or documentation edits cannot drift
back to testing only the source-tree module form.

\subsection{Empty Newick Export Guard}

\texttt{export\_hogenom\_rates\_from\_checkpoint.py} now rejects empty Newick
species-tree files before constructing a blank leaf label.  The check matches
the retained HOGENOM optimizer parser and keeps empty input files from becoming
valid-looking one-row rate exports or later tensor-shape errors.

\subsection{Path Config Validation}

\texttt{RunConfig.from\_dict()} now rejects missing or \texttt{null} required
\texttt{species\_tree}, \texttt{families\_file}, and \texttt{out\_dir} fields
and rejects non-string path values before path normalization.  The CLI mirrors
that check for \texttt{--config} input, so malformed JSON config files report
an \texttt{argparse} error instead of a raw \texttt{TypeError} traceback.

\subsection{Source Archive Package-Data Guard}

The package CI job now inspects the built \texttt{*.tar.gz} source archive and
requires the bundled C++ preprocessing sources under
\texttt{gpurec/core/cpp/}.  This exercises the \texttt{MANIFEST.in} surface
that downstream source-distribution installers rely on, complementing the
wheel install and CLI smoke checks.

\subsection{Legacy Checkpoint Safe Loading}

The retained HOGENOM checkpoint rate exporter and legacy W\&B optimizer resume
path now use PyTorch's \texttt{weights\_only=True} loading mode and reject
non-dictionary checkpoint payloads.  This brings legacy script checkpoint
consumers in line with the supported workflow loader and removes the remaining
tracked \texttt{weights\_only=False} checkpoint loads.

\subsection{Prefetch Close Lifecycle}

\texttt{GeneReconModel.close()} now marks background resident-batch prefetching
as closed before clearing pending futures and shutting down the executor.
Subsequent batch selection or explicit prefetch scheduling no longer recreates
a worker after the model has been closed, preventing accidental CPU work and
thread leakage in notebooks, services, or long audit runs.

\subsection{Sampling Output Documentation}

The project README now matches the sampling workflow's output layout:
per-sample RecPhyloXML and event-count files live under
\texttt{output\_gpurec/reconciliations/all/}, while aggregate summaries remain
under \texttt{output\_gpurec/reconciliations/}.  A source guard keeps the
README tied to the current \texttt{event\_counts.tsv},
\texttt{totalSpeciesEventCounts.txt}, and \texttt{totalTransfers.txt} outputs.

\subsection{Rate Export Checkpoint Payload Validation}

\texttt{export\_hogenom\_rates\_from\_checkpoint.py} now validates the tensor
shape and structure of safe-loaded checkpoint payloads before deriving D/L/T
rates.  Missing \texttt{theta} tensors, malformed branch-scaled payloads, and
branch/species row mismatches now raise explicit \texttt{ValueError}s instead
of leaking raw \texttt{KeyError}, \texttt{AttributeError}, or indexing failures.

\subsection{Sampling Singleton Aggregation}

The RecPhyloXML sampling parser now derives \texttt{singletons} from each
species' final copy count instead of incrementing it once per leaf.  A species
with two sampled gene copies is no longer reported as two singleton events,
while one-copy species still contribute one singleton to the aggregate output.

\subsection{Global Scheduler Split-Count Consistency}

The global phased-wave scheduler now treats \texttt{split\_parents\_sorted} as
the source of truth for per-clade split counts.  Supplied
\texttt{split\_counts} metadata is accepted only when it matches those derived
counts exactly, and out-of-range split parent ids now fail with an explicit
\texttt{ValueError} before scheduling can build a non-topological wave layout.

\subsection{Python Support Range Metadata}

The package metadata now declares \texttt{requires-python = ">=3.10,<3.13"},
matching the CI matrix and PyPI classifiers for Python 3.10 through 3.12.
The release metadata guard asserts that these supported versions remain
documented together, avoiding accidental advertisement of untested future
Python versions.

\subsection{Direct RunConfig Float Normalization}

\texttt{RunConfig} now normalizes direct Python API float controls the same way
integer controls are normalized.  Numeric strings and integral values are
stored as floats, while booleans are rejected before they can masquerade as
rates, tolerances, or optimizer learning rates in downstream workflow code.

\subsection{Batch Planner Family Index Validation}

The shared resident/chunked batch planner now validates selected family indices
against the available count arrays before any packing policy runs.  Negative
indices no longer alias the last family through Python indexing, and positive
out-of-range indices now fail with a clear \texttt{ValueError} instead of a
late raw \texttt{IndexError} or inconsistent family metadata.

\subsection{SamplingConfig and Run Failure Ergonomics}

\texttt{SamplingConfig} now normalizes its integer controls with the same
helpers used by \texttt{RunConfig}, rejecting booleans and non-integral floats
before they can reach range loops, subprocess payloads, or Rust backtracking
arguments.  The \texttt{gpurec run} command also reports optimization failure as
a runtime exit status 1 instead of an argparse usage error, while still
refusing to invoke sampling after a failed optimization.

\subsection{Wheel Package-Data Verification}

The release CI package job now checks required runtime C++ preprocessing sources
inside both the source archive and the built wheel.  This closes the gap where
\texttt{MANIFEST.in} could keep the sdist healthy while a broken
\texttt{tool.setuptools.package-data} entry silently produced wheels missing the
\texttt{gpurec/core/cpp/*.cpp} and \texttt{*.hpp} files needed by runtime
extension compilation.

\subsection{Batch-Control Integer Normalization}

Shared batch-planning controls now reject booleans and non-integral floats
before converting to integers.  This covers \texttt{family\_chunk\_size},
\texttt{clade\_budget}, selected family indices, \texttt{total}, and
\texttt{max\_wave\_size}; the chunked uniform API performs the same validation
before CUDA setup or filesystem IO, so invalid public constructor arguments
produce immediate \texttt{ValueError}s instead of silently changing batch
packing behavior.

\subsection{Resume Checkpoint Metadata Validation}

Workflow resume now validates checkpoint progress metadata before feeding it
back into optimization control flow.  The runner rejects malformed
\texttt{next\_step}, \texttt{best\_step}, \texttt{previous\_objective},
\texttt{best\_nll\_bits}, and \texttt{stable\_loss\_steps} values with
checkpoint-specific \texttt{RuntimeError}s, instead of letting strings,
booleans, fractional counters, or negative patience counters fail later inside
optimizer comparisons.

\subsection{CPU Unit Test README Coverage}

The tests README explicit CPU unit command now includes the legacy script unit
module that is selected by the marker-based CPU gate.  A release-metadata guard
parses that documented command and compares it with every non-GPU
\texttt{tests/unit/test\_*.py} module, so future CPU unit modules cannot drift
out of the bisect-friendly explicit command without a focused test failure.

\subsection{Memory-Policy Dimension Validation}

Uniform memory-policy helpers now validate dimension-like inputs before
estimating chunk payloads or choosing automatic policy candidates.  Boolean and
non-integral numeric values for wave rows, species counts, dense-state counts,
\texttt{family\_chunk\_size}, and auto-policy candidate lists now raise
\texttt{ValueError}s instead of being silently coerced by \texttt{int(...)}.

\subsection{Genewise Backtracking Parameter Layout}

Backtracking export now carries an explicit genewise layout hint when converting
one-dimensional solved probability tensors to species vectors.  This prevents
\texttt{[G]} genewise parameters from being mistaken for \texttt{[S]}
specieswise vectors when the selected resident batch has the same number of
families as species, so exported stochastic backtracking payloads select the
active family row before expanding scalar probabilities across species.

\subsection{Adaptive Iteration Boolean Validation}

The public \texttt{GeneReconModel} API now validates \texttt{adaptive\_iters}
as an actual boolean before CUDA setup or tree IO.  Factory calls and the direct
constructor reject values such as \texttt{"false"} with a clear
\texttt{ValueError}, instead of treating any non-empty object as truthy and
possibly raising the unrelated odd-\texttt{convergence\_check\_interval}
message.

\subsection{Rust Backtracking CI Collection Scope}

The Rust backtracking GitHub Actions job now runs the explicit CPU-safe
\texttt{tests/integration/test\_rust\_backtracking\_fixture.py} file instead of
collecting the entire non-GPU integration marker set after installing only
\texttt{pytest}.  This avoids collection-time imports of GPU integration modules
that require \texttt{torch}, while keeping the lightweight Rust fixture smoke in
the Rust-focused job.

\subsection{Backtracking Limit Type Validation}

Public stochastic backtracking entry points now validate \texttt{seed},
\texttt{max\_events}, and \texttt{num\_samples} as integer limits before model
access or payload construction.  Booleans, fractional values, and strings raise
parameter-specific \texttt{ValueError}s instead of leaking through as invalid
JSON/Rust CLI values or surfacing as low-context Python comparison errors.

\subsection{Quiet CLI Help Imports}

The installed \texttt{gpurec --help} and module-form
\texttt{python -m gpurec.cli --help} release smokes no longer import the
workflow, model, C++ preprocessing-extension, or Torch stacks just to render
argparse help.  The CLI lazily imports workflow configuration and execution
helpers only after a real subcommand is parsed, and the top-level package
exports are now lazy attributes so importing \texttt{gpurec.cli} does not
eagerly import the CUDA-only public API.  A release-metadata unit guard runs
both documented help commands with \texttt{CUDA\_VISIBLE\_DEVICES=''} and
asserts that stderr stays empty.

\subsection{Preprocess Cache Split Clade Validation}

Family preprocessing cache validation now checks that
\texttt{split\_parents\_sorted} and \texttt{split\_leftrights\_sorted} contain
only clade IDs inside the cached CCP range.  Corrupt or stale caches with
negative clade IDs, or IDs greater than or equal to \texttt{C}, fail during
safe cache loading with a field-specific \texttt{RuntimeError} instead of
surviving until batching reindexes tensors.

\subsection{Resident-Batch Control Validation}

\texttt{GeneReconModel} now validates resident-batch controls before CUDA
device checks, tree parsing, or dataset preprocessing.  Direct construction and
the public tree/AleRax factories reject non-integral
\texttt{family\_chunk\_size}, invalid \texttt{clade\_budget} values,
non-boolean \texttt{lazy\_preprocess}, and boolean, fractional, negative, or
unparseable \texttt{prefetch\_batches} values with parameter-specific
\texttt{ValueError}s.  The constructor preserves the previous meaning of
\texttt{family\_chunk\_size=None}: only an explicitly supplied chunk-size
control requests resident batching.

\subsection{Boolean Control Validation}

Additional public boolean controls now reject truthy strings and other
non-boolean values before CUDA setup or preprocessing.  \texttt{GeneReconModel}
validates \texttt{use\_pruning} in both direct and factory construction,
factory methods validate \texttt{refresh\_preprocess\_cache}, and
\texttt{GeneDataset} validates cache refresh before loading the C++ extension
or touching input paths.  This prevents values such as \texttt{"false"} from
silently enabling pruning or cache refresh work.

\subsection{Species Cache Topology Validation}

Species preprocessing cache validation now checks that cached topology tensors
only contain valid encoded species IDs.  \texttt{s\_C12\_indexes} entries must
fall inside \texttt{[0, S)}, and \texttt{s\_P\_indexes} entries must fall
inside \texttt{[0, 2S)} to account for the second-child parent encoding.
Corrupt species cache files therefore fail during safe cache loading instead
of later raising raw tensor indexing errors in species-tree helper code.

\subsection{GeneReconModel Dtype Validation}

\texttt{GeneReconModel} now validates its floating-point dtype contract before
theta initialization, CUDA checks, or file IO.  The public tree and AleRax
factories and the direct constructor accept only \texttt{torch.float32} and
\texttt{torch.float64}, matching the retained CUDA backward path, and reject
strings, integer dtypes, and unsupported floating dtypes with a clear
parameter-specific \texttt{ValueError}.

\subsection{Runtime Ninja Dependency}

The core package metadata now declares \texttt{ninja>=1.11} as a runtime
dependency because CPU preprocessing builds the C++ extension through
\texttt{torch.utils.cpp\_extension.load()}, which requires the Ninja executable.
A release-metadata unit guard parses \texttt{pyproject.toml} and asserts that
the core dependency list includes \texttt{ninja}, preventing fresh installs from
silently losing the build backend required before compiler/OpenMP checks begin.

\subsection{Uniform Chunked Boolean Validation}

\texttt{UniformChunkedReconModel} now validates
\texttt{refresh\_preprocess\_cache}, \texttt{use\_pruning},
\texttt{warm\_start\_E}, \texttt{profile}, and
\texttt{set\_optimized\_env} before CUDA device checks, file probing, or
preprocessing.  The direct constructor and the \texttt{from\_trees},
\texttt{from\_folder}, and \texttt{from\_alerax\_families} factories reject
truthy strings such as \texttt{"false"} with parameter-specific
\texttt{ValueError}s.  Invalid \texttt{set\_optimized\_env} values also fail
before optimized environment defaults are installed.

\subsection{Checkpoint Theta Finiteness}

Checkpoint loading now validates that \texttt{theta} is a floating-point tensor
with only finite values before resume code can restore it into model state.
Corrupt or failed-run checkpoints containing \texttt{NaN}, \texttt{Inf}, or
integer theta payloads now fail at the checkpoint boundary with
\texttt{RuntimeError}s instead of surfacing later as nonfinite objectives,
gradients, or backtracking payloads.

\subsection{Gene Tree Sequence Validation}

Explicit tree constructors now validate \texttt{gene\_trees} as a non-empty
sequence of family path entries before CUDA setup or preprocessing extension
loading.  Bare strings and single \texttt{Path} objects are rejected as a
single-path API mistake instead of being interpreted as iterables of
characters or path components.  The shared core normalizer enforces the same
contract for lower-level \texttt{GeneDataset} callers before the C++ extension
is loaded.

\subsection{Backtracking Environment Binary Paths}

\texttt{GPUREC\_BACKTRACK\_BIN} now resolves path-like values against the
caller's current working directory before the Rust subprocess switches to the
repository root.  Relative paths such as \texttt{bin/gpurec-backtrack},
explicit \texttt{./...} paths, absolute paths, and \texttt{Path} objects are
therefore stable across the subprocess \texttt{cwd}; bare command names remain
unresolved so they can still be found through \texttt{PATH}.

\subsection{Backtracking Progress Note Currency}

\texttt{docs/stochastic-backtracking-progress.md} now matches the current Rust
backtracking dependency and verification path.  It documents the pinned
\texttt{rustree} git dependency instead of an old local checkout requirement,
uses locked Cargo commands, and points to the current
\texttt{tests/integration/test\_rust\_backtracking\_fixture.py} smoke.  A
release-metadata unit guard keeps the archived progress note aligned with the
current Rust CI commands.

\subsection{Uniform Factory Dtype Validation}

\texttt{UniformChunkedReconModel} now uses one dtype validator for direct
construction and factory kwargs.  The \texttt{from\_trees},
\texttt{from\_folder}, and \texttt{from\_alerax\_families} factories reject
unsupported dtypes before CUDA device checks, AleRax parsing, or folder/file
probing, so invalid values such as \texttt{torch.int64},
\texttt{torch.float16}, or \texttt{"float32"} surface as parameter-specific
\texttt{ValueError}s instead of unrelated CUDA or IO errors.

\subsection{Optimizer Phase Checkpoint Compatibility}

Optimization checkpoints now record the phase that produced the serialized
optimizer state.  Resume only reloads an optimizer state when the checkpoint
phase matches the phase selected for \texttt{next\_step}; otherwise it discards
the state with \texttt{resume\_optimizer\_reason=phase\_mismatch}.  This
prevents \texttt{adam-lbfgs} resumes at the Adam/LBFGS boundary from loading
Adam moments and learning-rate metadata into a freshly constructed LBFGS
optimizer.

\subsection{Non-GPU Integration CI Gate}

The Rust backtracking CI job now runs the marker-selected
\texttt{pytest -q -m "integration and not gpu"} gate instead of one hard-coded
fixture path.  This aligns the workflow with \texttt{tests/README.md} and keeps
future CPU-safe integration tests under \texttt{tests/integration/} covered
without editing the workflow.  The release-metadata guard now asserts the
marker command is present and the old file-specific command is absent.

\subsection{Backtracking Smoke Build Guidance}

\texttt{tests/README.md} now makes the prebuilt-binary backtracking smoke
reproducible by documenting the required locked release build before setting
\texttt{GPUREC\_BACKTRACK\_BIN} to
\texttt{crates/gpurec-backtrack/target/release/gpurec-backtrack}.  A
release-metadata guard checks that the tests README keeps the build command,
environment variable, and targeted stochastic backtracking smoke together.

\subsection{Resume Checkpoint Identity Validation}

Optimization resume now validates checkpoint identity before restoring model
parameters.  Saved configuration fields that define the run identity
(\texttt{species\_tree}, \texttt{families\_file}, \texttt{mode},
\texttt{start}, and \texttt{max\_families}) are compared with the active
\texttt{RunConfig}, with path fields normalized to absolute paths, and saved
\texttt{family\_names} must match the current model ordering.  This prevents a
stale checkpoint from overwriting theta rows or convergence metadata for a
different family set or optimizer mode.

\subsection{Installed Wheel Smoke Isolation}

The package CI job now runs its installed-wheel CLI smoke from a fresh
\texttt{mktemp} directory after installing \texttt{dist/*.whl}.  The smoke also
imports \texttt{gpurec} and rejects paths under \texttt{GITHUB\_WORKSPACE},
while requiring the module to resolve from an installed
\texttt{site-packages} or \texttt{dist-packages} location.  The release-metadata
guard checks the temp-directory handoff and import-path assertions so the smoke
continues to verify the built artifact instead of the checkout tree.

\subsection{Scoped Release Cleanup Guidance}

\texttt{docs/release-readiness.md} no longer recommends a bare ignored-file
cleanup before packaging.  The preview and removal commands now scope
\texttt{git clean -Xd} to \texttt{build}, \texttt{dist}, and
\texttt{*.egg-info} pathspecs, preserving ignored HOGENOM datasets, local tool
checkouts, W\&B runs, and caches that may live beside the source tree.  A
release-metadata guard rejects exact bare cleanup commands and requires the
scoped preview and removal commands to stay in the guide.

\subsection{Final Checkpoint Resume Step}

Final optimization checkpoints now keep the diagnostic row step separate from
the optimizer resume cursor.  \texttt{save\_checkpoint} accepts an explicit
\texttt{next\_step} override; ordinary loop checkpoints still default to
\texttt{step + 1}, while final \texttt{best.pt} and \texttt{latest.pt} saves
record \texttt{next\_step=final\_step}.  A fake-runner regression runs
\texttt{steps=1}, asserts final \texttt{latest.pt} records \texttt{step=1} and
\texttt{next\_step=1}, then resumes with \texttt{steps=2} and verifies optimizer
step 1 is recorded before \texttt{final\_eval} step 2.

\subsection{Sampling Checkpoint Identity Metadata}

Checkpoint compatibility validation is now shared by optimization resume and
sampling restore.  Checkpoints record \texttt{species\_names} alongside
\texttt{family\_names}, and the shared guard rejects family-order or
species-order mismatches before theta is copied into a rebuilt model.  Sampling
also closes the loaded model when checkpoint validation or an empty family
selection fails, so early error paths no longer leave workflow model resources
open.

\subsection{Raw Theta Artifact Contract}

The production README and release-readiness notes now distinguish
metadata-bearing checkpoints from the raw \texttt{theta\_final.pt} tensor
export.  \texttt{checkpoints/best.pt} and \texttt{checkpoints/latest.pt} are
documented as the artifacts for resume, sampling, and restore workflows, while
\texttt{theta\_final.pt} is explicitly documented as inspection/custom-analysis
output without run configuration, family ordering, or species ordering metadata.
A regression writes a bare tensor to a \texttt{theta\_final.pt}-style path and
checks that the normal checkpoint loader rejects it as a non-dictionary
checkpoint payload.

\subsection{Raw Theta Sampling CLI Hint}

\texttt{gpurec sample --checkpoint theta\_final.pt} now turns the low-level
non-dictionary checkpoint payload error into an actionable CLI message.  When a
raw theta export is passed as the sampling checkpoint, the CLI still reports the
checkpoint loader failure, but now also points users to
\texttt{checkpoints/best.pt} or \texttt{checkpoints/latest.pt} and explicitly
identifies \texttt{theta\_final.pt} as the wrong artifact for sampling.

\subsection{Packaged Minimal Example}

The checked minimal workflow example is now included in source distributions
instead of being advertised only by a README that ships without the referenced
files.  \texttt{MANIFEST.in} includes the minimal JSON config and tiny species,
family, gene-tree, and mapping files, and the package CI source-archive check
now verifies those documented examples separately from wheel package data.  The
example's configured output and preprocessing-cache paths are also covered by
\texttt{examples/output/} in \texttt{.gitignore}, with a unit guard that runs
\texttt{git check-ignore} against both configured paths.  The same manifest
guard keeps the existing native C++ source inclusion explicit so packaging the
example cannot silently drop extension build inputs from the source archive.

\subsection{CLI Input Path Preflight}

\texttt{gpurec optimize} and \texttt{gpurec run} now validate the species-tree
and AleRax family-list paths immediately after normalizing \texttt{RunConfig}
from JSON and CLI flags.  Missing or directory-valued inputs are reported as
explicit \texttt{--species-tree} or \texttt{--families-file} argument errors
before optimization setup can reach device probing or model construction.  The
CLI tests now create tiny AleRax-compatible input fixtures for monkeypatched
workflow calls, and the new regression cases verify that missing input files
exit through argparse without CUDA noise, tracebacks, or an optimization call.

\subsection{CLI Runtime Exit Semantics}

\texttt{gpurec optimize}, \texttt{gpurec sample}, and both workflow phases of
\texttt{gpurec run} now separate configuration construction errors from
workflow runtime exceptions.  Configuration and input validation still report
through argparse with exit code 2, while exceptions raised by optimization or
sampling workflows exit with status 1 and an error line that does not include
the argparse usage banner.  The CLI regression tests cover direct
optimization, direct sampling, and combined run mode so operational failures
are no longer presented as command-line syntax mistakes.

\subsection{Backtracking Binary Preflight}

The Rust backtracking bridge now validates path-like \texttt{backtrack\_binary}
inputs and \texttt{GPUREC\_BACKTRACK\_BIN} values before invoking
\texttt{subprocess.run}.  Explicit paths must point to executable files, and
bare command names must be discoverable on \texttt{PATH}.  Missing binaries,
non-executable files, and missing environment-provided command names now raise
clear gpurec \texttt{RuntimeError}s before a temporary payload is handed to a
child process, while the existing cargo fallback remains available when no
binary override is supplied.

\subsection{Run-Mode Sampling Option Preflight}

\texttt{gpurec run} now validates sampling-only options such as
\texttt{--samples}, \texttt{--seed}, \texttt{--family-start},
\texttt{--sample-max-families}, and \texttt{--max-events} before launching
optimization.  This keeps combined optimize-and-sample runs from spending GPU
or CPU time on optimization only to reject an invalid sampling option after a
checkpoint is produced.  The regression test monkeypatches optimization to
prove invalid sampling options exit through argparse before any workflow call.

\subsection{Sampling Empty-Selection Output Preservation}

\texttt{SamplingRunner.run()} now validates the requested family range before
clearing any previous reconciliation outputs.  An empty selection such as a
\texttt{family\_start} beyond the available family count still closes the model
and reports a \texttt{ValueError}, but it no longer deletes prior XML files,
per-sample event-count files, or aggregate summaries before failing.  The
regression test seeds those stale outputs and verifies they are preserved on
the empty-selection path while the successful sampling test still covers normal
cleanup before writing a fresh result set.

\subsection{CUDA Device Index Validation}

CUDA device validation is now centralized in
\texttt{gpurec.api.\_validation.require\_cuda\_device}.  The helper wraps
malformed device specifications in gpurec-owned \texttt{ValueError}s and
rejects explicit CUDA indices greater than or equal to
\texttt{torch.cuda.device\_count()} before model construction begins.  The
workflow model factory now uses the same helper instead of a string-prefix
check, so \texttt{cuda:99} fails with a clear configuration error instead of
reaching a later CUDA allocation path.  A new CPU-only validation test module
monkeypatches CUDA availability and device count, and the explicit test-command
documentation was updated so the docs guard continues to match the marker
gate.

\subsection{Empty Checkpoint Error Wrapping}

\texttt{load\_checkpoint()} now treats \texttt{EOFError} from
\texttt{torch.load(..., weights\_only=True)} as an unsafe or malformed
checkpoint load failure.  Empty or truncated checkpoint files therefore produce
the same gpurec-owned \texttt{RuntimeError} as other invalid serialized
artifacts.  The CLI regression creates an empty \texttt{.pt} file and verifies
\texttt{gpurec sample --checkpoint} exits without usage text or a Python
traceback while still showing the checkpoint path and recovery-oriented loader
message.

\subsection{RunConfig Direct Boolean Normalization}

\texttt{RunConfig(...)} now applies the same boolean type contract as JSON
configuration loading.  Direct construction rejects non-\texttt{bool} values
for \texttt{refresh\_preprocess\_cache} and \texttt{adaptive\_iters} instead
of preserving truthy strings such as \texttt{"false"}.  This keeps programmatic
callers, CLI JSON input, and checkpoint-loaded configs aligned on a single
\texttt{true}/\texttt{false} validation rule before downstream workflow logic
observes those controls.

\subsection{YAML Config CLI Import Preflight}

\texttt{gpurec optimize --config ...yaml} now rejects Hydra-style YAML before
importing \texttt{RunConfig}.  This keeps the installed CLI's documented flat
JSON validation path lightweight: bad YAML exits through argparse with the
flat-JSON guidance instead of first importing the workflow package and any
CUDA/Triton-dependent modules reachable from it.  The regression runs the CLI
in a fresh Python subprocess, catches the expected \texttt{SystemExit}, and
asserts no \texttt{gpurec.workflow} module was imported on that failure path.

\subsection{Cargo Fallback Preflight}

The stochastic backtracking bridge now validates the implicit Cargo fallback
before building a subprocess command.  If no explicit
\texttt{backtrack\_binary} or \texttt{GPUREC\_BACKTRACK\_BIN} value is
configured, the source-manifest fallback still uses
\texttt{cargo run --locked --quiet}, but it first checks that
\texttt{cargo} is discoverable on \texttt{PATH}.  Missing Cargo now raises a
gpurec \texttt{RuntimeError} that points users either to Rust/Cargo
installation or to the explicit binary configuration path, and the fallback
unit tests monkeypatch \texttt{shutil.which} so they are independent of the
local developer machine.

\subsection{Sampling Seed \texttt{u64} Bounds}

Sampling seed validation now matches the Rust stochastic backtracking contract.
Public backtracking helpers reject seeds above \texttt{2**64 - 1}, and
\texttt{SamplingConfig} applies the same bound to configured base seeds.  The
sampling workflow also validates the largest derived per-family/per-sample seed
after resolving the selected family range and before clearing prior outputs.
Overflowing derived ranges now fail with a gpurec \texttt{ValueError}, close
the loaded model, preserve existing reconciliation outputs, and never invoke
the Rust sampler.

\subsection{Sampling Event-Counts TSV Escaping}

\texttt{event\_counts.tsv} is now written through Python's
\texttt{csv.writer} with a tab delimiter instead of manual string
concatenation.  Family names containing tabs or other TSV-significant
characters are quoted correctly, so the table keeps the documented
\texttt{family}, \texttt{sample}, and event-count columns without shifting
downstream fields.  The regression parses the generated file with
\texttt{csv.reader} and verifies a tabbed family label remains one logical
field with the expected column count.

\subsection{\texttt{gpurec run} Sampling Checkpoint Provenance}

\texttt{gpurec run} now samples from the checkpoint reported by the optimizer
result instead of re-discovering \texttt{best.pt} by filename after
optimization.  \texttt{OptimizationResult} records the checkpoint actually
selected for downstream sampling: a \texttt{best.pt} written during the current
optimization when the run improved, otherwise the fresh \texttt{latest.pt}
written at completion.  This prevents a stale \texttt{best.pt} already present
in the output directory from being sampled after a resumed or non-improving
run.  Regression tests cover both the CLI handoff and the optimizer case where
no new best checkpoint is written.

\subsection{Config-Relative JSON Workflow Paths}

Flat JSON \texttt{RunConfig} files now resolve path fields relative to the JSON
file's directory before dataclass normalization.  This applies to
\texttt{species\_tree}, \texttt{families\_file}, \texttt{out\_dir},
\texttt{preprocess\_cache}, and \texttt{resume\_from}, making packaged example
configs portable when invoked outside the repository root.  Explicit CLI path
flags still override config values after that rebasing step and remain relative
to the caller's current working directory.  The minimal example config now uses
paths relative to \texttt{examples/minimal-run-config.json}, and the README/CLI
help describe the distinction.

\subsection{Local Slow Test Markers}

The test collection hook no longer keeps a \texttt{SLOW\_TEST\_PATTERNS}
node-id allowlist.  The three known expensive checks now use explicit
\texttt{@pytest.mark.slow} decorators at the test definition, keeping runtime
intent local to the test file alongside the existing module-level GPU markers.
The source guard now rejects reintroducing node-id based marker inference in
\texttt{tests/conftest.py}, and \texttt{tests/README.md} documents that slow
intent belongs beside the test.

\subsection{Pytest-Managed Test Caches}

The specieswise uniform GPU tests no longer write preprocessing artifacts into
a shared absolute \texttt{/tmp/gpurec\_preprocess\_cache} directory.  Their
model helper now receives a pytest-managed temporary cache directory from each
test, with separate directories where a test builds multiple models.  A
source-level guard rejects future hardcoded \texttt{/tmp/} paths under
\texttt{tests/*.py}, keeping test caches isolated from other runs and
developer machines.

\subsection{Historical Backlog Note Labeling}

\texttt{docs/core-simplification-suggestions.md} now explicitly identifies
itself as a historical cleanup snapshot rather than a current backlog.  The
status note names the major suggestions that have already landed or been
superseded and asks maintainers to revalidate each item against the current
source tree before using it as active work.  \texttt{docs/release-readiness.md}
also now distinguishes remaining manual release blockers from packaging checks
that are already covered by CI.

\subsection{Kernel Test Marker Classification}

\texttt{tests/kernels} now participates in the coarse marker taxonomy as
integration-level coverage.  The collection hook applies
\texttt{pytest.mark.integration} to kernel tests in addition to
\texttt{tests/integration}, so \texttt{-m "not unit and not integration"} no

\subsection{Shared GPU Tree Data Fixtures}

The unit GPU tests now use the shared \texttt{tests/conftest.py} fixtures for

\texttt{test\_trees\_1000} context when its one-gene fixture is unavailable.
A source guard prevents unit test modules from reintroducing literal dataset
directory setup outside the central fixtures.

\subsection{Repository Hygiene Test Split}

Repository-wide source guards and documentation checks now live in

\subsection{CLI Workflow Test Split}

\subsection{Tracked Root Test Module Guard}

\subsection{Generated Artifact Tracking Guard}

The repository hygiene tests now also protect generated runtime and build roots

\subsection{README Distribution-Scope Clarifications}

The README now scopes \texttt{examples/minimal-run-config.json} to source

configuration that users can copy beside their own input files.  The sampling

\subsection{Rust Backtracking Source Archive}

\texttt{MANIFEST.in} now includes the Rust backtracking crate's

checkout or unpacked source archive, while installed wheels remain on the
prebuilt-binary path through \texttt{GPUREC\_BACKTRACK\_BIN} or
\texttt{--backtrack-binary}.

\subsection{Log2 Utility Unit Coverage}

The base-2 log helpers now have direct CPU unit coverage instead of relying on
indirect model tests.  The new \texttt{tests/unit/test\_log2\_utils.py} module
checks that \texttt{\_safe\_log2\_internal()} returns \texttt{-inf} with zero
gradient for non-positive inputs, that \texttt{logsumexp2()} matches a
natural-log reference while preserving all-\texttt{-inf} slices and
\texttt{keepdim} shape, and that \texttt{log2\_softmax()} both normalizes

\subsection{Term Helper Unit Coverage}

\texttt{gather\_E\_children()} now has focused CPU unit coverage for its

the unsupported-rank \texttt{ValueError} message that reports the offending
input shape.

\subsection{Scheduling Helper Unit Coverage}

\texttt{compute\_clade\_waves()} now has direct CPU tests for the Python

\texttt{tests/unit/test\_scheduling.py} module checks required metadata errors,

\subsection{Species Helper Unit Coverage}

The CPU species-tree helper layer now has direct coverage for its compact

module checks parent-vector construction with requested dtype, child and parent
topology tensors, compact internal-node levels, cache reuse, mismatched helper
length errors, cycle detection, and sparse uniform ancestor matrix construction.

\subsection{Global Scheduler Test Path Hygiene}

The global wave scheduler source-guard test no longer assumes pytest is invoked
from the repository root.  It resolves checked source files from
\texttt{\_\_file\_\_} and deliberately changes the current working directory
before reading them, so future scheduler tests that inspect repository files
cannot silently depend on launch location.

\subsection{Shared Tiny AleRax Test Inputs}

The tiny one-family AleRax fixture used by command-line workflow tests now
lives in a shared unit-test helper.  The CLI workflow tests and AleRax family
parser tests both use that helper for their minimal \texttt{species},
\texttt{families}, gene-tree, and mapping files, reducing duplicated fixture
text while keeping each test's behavior-specific assertions local.

\subsection{CLI Alias Normalization}

\texttt{gpurec optimize} now accepts the same dtype and resident-batch packing
aliases that workflow configuration normalization already supported.  The
parser normalizes dtype aliases such as \texttt{fp32}, \texttt{single},
\texttt{double}, and \texttt{torch.float64} to canonical \texttt{float32} or
\texttt{float64} values, and normalizes batch-packing aliases such as
\texttt{input-order}, \texttt{ffd}, \texttt{clade-ffd}, and
\texttt{critical-path-first-fit} to the canonical workflow packing names.

\subsection{Pytest Marker Taxonomy Cleanup}

\texttt{pytest.ini} no longer registers unused \texttt{gradient} or
\texttt{autograd} markers.  It now registers a \texttt{kernel} marker, and the
collection hook applies it to \texttt{tests/kernels} alongside the existing
\texttt{integration} marker.  The tests README documents that layout mapping,
and a repository hygiene guard checks that the marker registry, collection hook,
and documentation stay aligned.

\subsection{Optimization Stopping Helper}

\texttt{OptimizationRunner.run()} now uses one private helper for per-step
stopping decisions.  Gradient tolerance, loss-change patience, and
best-likelihood patience previously appeared once inside the ordinary
Adam/Adagrad path and again after the LBFGS path; the shared helper preserves
the same priority order while keeping checkpoint, row-recording, and logging
logic independent of optimizer phase.  A new focused optimization workflow test
module covers the helper's ordering and no-stop cases without constructing a
CUDA model.

\subsection{Optimization Resume State Helper}

\texttt{OptimizationRunner.run()} now delegates checkpoint resume metadata
parsing to a small \texttt{\_ResumeState} dataclass and
\texttt{\_resume\_state\_from\_payload()} helper.  The runner still owns model
compatibility checks, theta restoration, optimizer construction, and optimizer
state restoration, but the scalar resume fields now have one focused validation
path for \texttt{next\_step}, best likelihood metadata, previous objective, and
stable-loss patience.  The invalid metadata cases moved from the large workflow
test module into \texttt{tests/unit/test\_optimization\_workflow.py}, where the
helper can be exercised directly without constructing a fake optimization
runner.

\subsection{Batching Scheduler Invariant Guards}

The global batching scheduler now rejects malformed CCP split child IDs before
constructing dependency adjacency lists.  \texttt{\_family\_schedule\_data()}
validates both child columns in \texttt{split\_leftrights\_sorted}, including
negative and out-of-range clade IDs, so bad metadata reports an explicit
\texttt{ValueError} instead of relying on negative indexing or an opaque
\texttt{IndexError}.  \texttt{build\_wave\_layout()} now also checks that
\texttt{waves} and \texttt{phases} have matching lengths before building the
layout tensors, preventing silent phase drops and late list-index failures.

\subsection{Empty Collate Batch Guard}

\texttt{collate\_gene\_families()} now rejects an empty family batch at the
entry point with a clear \texttt{ValueError}.  Previously an empty list reached
the tensor assembly phase and failed through \texttt{torch.cat([])}, which made
the public contract depend on an incidental PyTorch error instead of a
domain-specific message.

\subsection{Shared RecPhyloXML Traversal}

RecPhyloXML namespace handling, root-clade discovery, direct child traversal,
and \texttt{eventsRec} extraction now live in
\texttt{gpurec.recphyloxml}.  \texttt{recphyloxml\_event\_counts()} and the
sampling workflow's species/transfer aggregate builder both use those helpers,
so future changes to XML traversal cannot drift independently across the
AleRax-style event count files and sampling summary outputs.  The new
\texttt{tests/unit/test\_recphyloxml.py} module covers namespaced documents,
multiple \texttt{recGeneTree} blocks, and the shared traversal path used by
both backtracking and sampling aggregation.

\subsection{Shared Family Layout Helpers}

Resident and chunked-uniform model setup now share the CPU-side family layout
plumbing in \texttt{gpurec.api.\_family\_layout}.  The helper builds
family-indexed CCP items, local clade offsets, root rows, scheduled waves, and
wave-layout tensors for the caller's family order.  \texttt{GeneReconModel}
uses it for full-resident and resident-batch static states, while
\texttt{UniformChunkedReconModel} uses the same helper for chunk layout
construction.  Family-specific origination-probability slicing also moved to
the same helper so resident and chunked evaluation setup preserve identical
\texttt{None}, shared \texttt{[S]}, and family-specific \texttt{[F,S]}
semantics without duplicate tensor-indexing code.

\subsection{Shared Environment Flag Parsing}

CUDA-path runtime toggles now use shared parsing helpers in
\texttt{gpurec.core.\_helpers}.  \texttt{Pi\_wave\_forward()} and
\texttt{Pi\_wave\_backward()} no longer duplicate their environment truth table
for disabled tokens such as \texttt{0}, \texttt{false}, \texttt{no}, and
\texttt{off}.  The backward self-loop mode toggles also share the exact
\texttt{auto}/required parsing used by the existing CUDA fallback logic.  This
keeps performance-path flags homogeneous while remaining CPU-testable through
pure helper tests.

\subsection{CLI Resume Checkpoint Preflight}

\texttt{gpurec optimize} and \texttt{gpurec run} now validate
\texttt{--resume-from} in the same CLI preflight as \texttt{--species-tree}
and \texttt{--families-file}.  Missing resume checkpoints therefore fail with
an argparse error before workflow execution, model construction, or CUDA device
checks.  The focused CLI regressions cover both commands and assert that the
error names \texttt{--resume-from}, includes the missing path, and does not
emit CUDA noise or a traceback.

\subsection{Release README Metadata Guard}

The release metadata checker now validates that \texttt{pyproject.toml}
declares readable project README metadata.  It accepts both the current
\texttt{readme = "README.md"} form and the table form with
\texttt{readme.file}, while reporting missing README metadata or a missing
declared README file as release blockers.  The current project still reports
only the pre-existing license blockers, so this guard tightens packaging
hygiene without changing the outstanding licensing decision.

\subsection{CPU CI Workflow Hardening}

The CPU GitHub Actions workflow now declares least-privilege repository token
access with \texttt{permissions: contents: read} and cancels superseded runs
through a branch-scoped \texttt{concurrency} group.  The release metadata test
suite includes a workflow-text guard that verifies both top-level blocks appear
before \texttt{jobs:}, preserving the existing unit, Rust backtracking, and
package jobs while avoiding unnecessary CI work on stale pushes.

\subsection{Workflow Config Path Handling}

Flat JSON workflow config files are now normalized before reading, so
home-directory config paths work through both \texttt{RunConfig.from\_json()}
and \texttt{gpurec optimize --config}.  Relative path fields still resolve
from the expanded config file directory, keeping portable checked-in configs
usable outside the caller's working directory.  \texttt{RunConfig.write\_json()}
also creates missing parent directories and expands home-directory output
paths, making round-tripped workflow configs safer to write into external run
directories.

\subsection{Sampling Backtracking Preflight}

\texttt{SamplingRunner.run()} now validates Rust backtracking command
availability before loading checkpoints or constructing a workflow model.  The
preflight reuses the existing \texttt{GPUREC\_BACKTRACK\_BIN},
\texttt{--backtrack-binary}, and locked Cargo fallback resolver, so installed
sampling still reports the same actionable binary/setup errors but does so
before any CUDA-facing or checkpoint-model work can start.

\subsection{Positive-Even Solver Iteration Validation}

The direct Python API now validates \texttt{fixed\_iters\_Pi} through a shared
\texttt{positive\_even\_int()} helper in \texttt{gpurec.api.\_validation}.
\texttt{GeneReconModel}, \texttt{UniformChunkedReconModel}, and their factory
keyword preflight paths use the same helper instead of repeating
positive-integer-plus-evenness checks.  This keeps direct constructor,
factory, and runtime solver-control errors homogeneous without changing the
CUDA execution paths.

\subsection{Workflow Positive-Even Iteration Validation}

\texttt{RunConfig} now normalizes \texttt{fixed\_iters\_pi} through a dedicated
\texttt{\_normalize\_positive\_even\_int()} helper instead of performing
positive-integer normalization in \texttt{\_\_post\_init\_\_()} and a separate
evenness check in \texttt{validate()}.  The workflow JSON/programmatic config
layer now mirrors the public model API's positive-even solver iteration
contract, with direct regression coverage for odd \texttt{fixed\_iters\_pi}
values before model construction or CUDA setup.

\subsection{Resume Progress Bound Validation}

\texttt{OptimizationRunner.run()} now rejects resume checkpoints whose
\texttt{next\_step} is greater than the configured \texttt{RunConfig.steps}
value.  The check runs after checkpoint identity compatibility and resume
metadata parsing, but before \texttt{restore\_model\_theta()}, optimizer
construction, or training-loop entry.  This turns a previously silent
over-complete resume into an actionable checkpoint error and prevents
\texttt{steps\_completed} metadata from exceeding the configured step budget.

\subsection{Workflow Dtype Canonicalization}

\texttt{RunConfig} now canonicalizes accepted dtype aliases such as
\texttt{fp32}, \texttt{single}, \texttt{double}, and
\texttt{torch.float64} to stable \texttt{float32}/\texttt{float64} strings at
the workflow config boundary.  The CLI dtype parser delegates to the same
helper, and checkpoint payload tests now verify that saved \texttt{config}
metadata stores the canonical dtype and still rehydrates through
\texttt{RunConfig.from\_dict()}.  This keeps JSON configs, CLI overrides, and
checkpoint metadata consistent without changing the runtime
\texttt{torch.dtype} used for model construction.

\subsection{Public Chunk and Wave Control Preflight}

The resident \texttt{GeneReconModel} API now validates optional wave-cap
controls, including \texttt{max\_wave\_size},
\texttt{max\_root\_wave\_size}, and \texttt{max\_dts\_partial\_rows}, at the
factory and direct-constructor boundary before CUDA setup or tree-file I/O.
The uniform chunked API now performs the same early rejection for
\texttt{family\_chunk\_size}, \texttt{max\_wave\_size},
\texttt{max\_root\_wave\_size}, \texttt{clade\_budget},
\texttt{batch\_packing}, and automatic policy candidate lists.  Numeric
nonpositive wave caps and invalid candidate entries now raise
\texttt{ValueError} from public validation code, while the established
uniform unbounded aliases \texttt{max\_wave\_size=None}, \texttt{"0"},
\texttt{"none"}, and \texttt{"null"} remain accepted.

\subsection{Public Index Selector Validation}

Public family, batch, and chunk selectors now share the same integral-value
validation style.  \texttt{GeneReconModel.family\_input()},
\texttt{select\_batch()}, and \texttt{activate\_family()} reject booleans,
fractional floats, and non-finite floats before range checks or batch
activation.  The backtracking export entry point validates
\texttt{family\_index} before delegating to model-specific helpers, so custom
model doubles receive normalized integer selectors.  The uniform chunked
\texttt{chunk\_indices} path now applies the same checks to list and tensor
selectors before duplicate and out-of-range detection.  Shared family batch
planning also rejects duplicate explicit family indices, preventing a selected
family from being scheduled twice in resident or chunked batches.

\subsection{Installed Sampling Documentation Contract}

The package workflow now keeps example fixtures source-archive-only by
rejecting \texttt{examples/} paths in wheels while still requiring them in the
sdist.  It also reads \texttt{examples/minimal-run-config.json} from the
source archive and verifies that the documented \texttt{species\_tree} and
\texttt{families\_file} targets are present beside it.  The installed-wheel
smoke now exercises \texttt{gpurec sample --help} and
\texttt{gpurec run --help}, checking that both commands advertise the external
backtracking binary controls expected for wheel installs.  Sampling checkpoint
help now points users to \texttt{checkpoints/best.pt} or
\texttt{checkpoints/latest.pt} and distinguishes those metadata-bearing files
from the raw \texttt{theta\_final.pt} tensor export.  The README and release
readiness notes now state that \texttt{gpurec run}'s sampling phase follows
the same \texttt{GPUREC\_BACKTRACK\_BIN} and \texttt{--backtrack-binary}
contract as \texttt{gpurec sample}.

\subsection{Sampling CLI Coverage and Loss-API Documentation}

The successful \texttt{gpurec sample} CLI path now has a CPU unit regression
that invokes \texttt{main()} with a dummy checkpoint and verifies every
user-facing sampling option forwarded into \texttt{SamplingConfig}, including
the \texttt{--sample-out-dir}/\texttt{--sampling-out-dir} aliases,
\texttt{--samples}, \texttt{--seed}, \texttt{--family-start},
\texttt{--sample-max-families}, \texttt{--max-events}, and
\texttt{--backtrack-binary}.  The README sampling example now shows an
explicit output directory and documents the family-window, seed, and event-cap
controls alongside the output layout.  The second-order optimization note was
updated away from stale private or removed symbols such as
\texttt{GeneReconModel.\_forward\_inference()}, generic
\texttt{model.nll()}, and the removed \texttt{global\_optimizer.py} helper.
It now names the current public no-grad loss probes:
\texttt{GeneReconModel.full\_loss\_for\_theta(theta)} for resident models and
\texttt{UniformChunkedReconModel.nll()} for chunked global models.  Repository
hygiene tests now guard those documentation contracts.

\subsection{Uniform Chunk Metadata Public Surface}

Parallel API/export reviews found that the uniform chunked integration tests
were still asserting on \texttt{UniformChunkedReconModel.\_state} internals for
chunk counts, solver iteration settings, dataset family counts, and built
chunk layout summaries.  The model now exposes a stable public metadata
surface for those use cases: \texttt{n\_families}, \texttt{family\_count},
\texttt{chunk\_count}, \texttt{fixed\_iters\_Pi},
\texttt{fixed\_iters\_E}, and tuple-valued \texttt{chunk\_metadata}.  The new
\texttt{UniformChunkMetadata} dataclass reports the chunk index, selected
family indices and names, gene tree paths, family/clade/split counts, wave
counts, and split-row sizes without exposing the internal resident wave-layout
dictionary.

\texttt{UniformChunkMetadata} is exported from \texttt{gpurec.api} and the
top-level \texttt{gpurec} namespace, and the top-level export test now checks
that \texttt{gpurec.\_\_all\_\_} stays aligned with its lazy-export map.  The
uniform chunked integration tests now use the public accessors instead of
reading \texttt{\_state}.  The README runtime-surface summary now calls out
public chunk metadata as the supported way to inspect resident uniform chunk
planning.

\subsection{CLI and Workflow Export Drift Guards}

The CLI-to-workflow configuration mapping now exposes its
\texttt{RunConfig} override field list as a single module-level tuple instead
of keeping the long copy loop inline in \texttt{\_run\_config\_from\_args()}.
A CPU-only regression test compares that tuple with the
\texttt{RunConfig} dataclass field set and with the parser destinations for
both \texttt{gpurec optimize} and \texttt{gpurec run}.  This turns future
configuration additions into an immediate test failure unless the matching CLI
flag and override path are added at the same time, while preserving the
existing \texttt{BooleanOptionalAction} override behavior for
\texttt{adaptive\_iters}.

The workflow root export policy was also made explicit.  Since top-level
\texttt{gpurec} already re-exported \texttt{RunConfig},
\texttt{SamplingConfig}, the workflow runners, and the workflow functions, it
now also re-exports the matching \texttt{OptimizationResult} and
\texttt{SamplingResult} dataclasses.  A dedicated workflow export parity test
checks every name in \texttt{gpurec.workflow.\_\_all\_\_} against the
top-level lazy-export map and object identity, so the two public workflow
barrels cannot silently drift apart.

\subsection{Release Metadata Validation and Example API Smokes}

The release metadata checker now validates the shape of declared license
metadata instead of only checking for the presence of a \texttt{license} field.
It accepts nonempty string metadata, \texttt{license.file} tables that point to
an existing file, and nonempty \texttt{license.text} tables, while reporting
clear errors for missing files, empty text, invalid table contents, or missing
metadata.  The repository still intentionally fails the release metadata check
only on the unresolved license blockers: no top-level \texttt{LICENSE}, no
\texttt{pyproject.toml} license metadata, and no license classifier.

The README now documents the top-level Python workflow shortcuts for
\texttt{RunConfig}, \texttt{SamplingConfig}, \texttt{optimize()}, and
\texttt{sample()}, with a note that \texttt{gpurec.workflow} exports the same
configs, runners, result dataclasses, and workflow functions.  Example tests
now guard those shortcuts and run the documented
\texttt{gpurec optimize --config examples/minimal-run-config.json} command path
with the optimizer monkeypatched, proving the checked example config reaches
the CLI-to-\texttt{RunConfig} boundary without requiring CUDA or optimizer
execution.

\subsection{Core Scheduling Input Validation}

The core batching and scheduling helpers now fail fast on inconsistent
metadata instead of relying on \texttt{zip()} truncation or unchecked tensor
remaps.  \texttt{compute\_clade\_waves()} and
\texttt{split\_phase\_waves()} reject mismatched wave and phase counts, while
\texttt{collate\_wave()} rejects mismatched family wave and offset counts.

The global wave layout path now validates every clade identifier before it is
used to index the permutation map.  Split child ids, split parent ids, leaf row
ids, root row ids, and each family \texttt{root\_clade\_id} must be in range,
and leaf row and column metadata must have matching lengths.  CPU-only tests
cover these invalid-value cases and the existing \texttt{max\_root\_wave\_size}
root-wave splitting behavior.

\subsection{Backtracking Binary Preflight and Wheel Guards}

The installed CLI now has a \texttt{gpurec backtrack-check} command that
validates the Rust backtracking binary resolution path without loading a
checkpoint.  It shares the same \texttt{--backtrack-binary} option text used by
\texttt{gpurec sample} and \texttt{gpurec run}, and the missing-binary
diagnostics now mention both the Python \texttt{backtrack\_binary} argument and
the CLI flag.  The README separates wheel-only binary setup from source-checkout
Cargo builds, and the release checklist documents the new preflight smoke.

The backtracking subprocess runner now preserves the caller's working directory
for externally supplied binaries, while keeping the source-root working
directory for the automatic Cargo fallback.  This avoids surprising installed
users who provide a binary through \texttt{GPUREC\_BACKTRACK\_BIN} or
\texttt{--backtrack-binary}.  The package workflow also rejects wheel artifacts
that contain a \texttt{gpurec-backtrack} executable name anywhere in the wheel,
not only the \texttt{crates/gpurec-backtrack} source directory.

\subsection{Rust Backtracking Seed and Limit Contracts}

The Rust backtracking crate now validates the sampling contracts that the
Python CLI documents.  Library multi-sample replay uses checked seed addition,
so a request such as base seed \texttt{u64::MAX} with multiple samples returns
an \texttt{InvalidInput} error instead of panicking in debug builds or wrapping
in release builds.  The crate also rejects \texttt{max\_events = 0} during
input preparation and has tests proving that a small positive cap stops
expansion deterministically.

The Rust CLI parser now rejects unknown dash-prefixed options, reports missing
option values with the option name, and supports \texttt{--max-events} as a
direct override for JSON fixtures.  Direct Rust help now advertises that cap,
and the stochastic backtracking notes record \texttt{--seed} and
\texttt{--max-events} support alongside multi-sample output.  The top-level
Python namespace now also exports \texttt{ensure\_backtracking\_available()} so
Python users have the same preflight affordance as \texttt{gpurec
backtrack-check}.

\subsection{Config Boundary and Checkpoint Progress Validation}

\texttt{RunConfig} and \texttt{SamplingConfig} now validate path-like public
constructor fields before handing values to \texttt{pathlib.Path}.  Direct
Python API calls therefore receive field-specific \texttt{ValueError}
diagnostics for bad \texttt{species\_tree}, \texttt{families\_file},
\texttt{out\_dir}, \texttt{preprocess\_cache}, \texttt{resume\_from},
\texttt{checkpoint}, and \texttt{backtrack\_binary} values instead of raw
type errors.  \texttt{RunConfig} also validates \texttt{device} as a parseable
Torch device string, so JSON configs and CLI invocations reject typos such as
\texttt{cdua} before any workflow or CUDA model construction.

Versioned checkpoints now require nonnegative \texttt{step} and
\texttt{next\_step} metadata, and the resume helper rejects inconsistent
progress pairs before restoring \texttt{theta}.  The valid checkpoint cursor
states are the regular post-step form \texttt{next\_step = step + 1} and the
final-evaluation form \texttt{next\_step = step}; malformed current-version
payloads such as \texttt{step=5,next\_step=0} now fail explicitly instead of
rewinding optimization progress after loading later parameters.

\subsection{Sampling Failure Artifact Preservation}

\texttt{SamplingRunner.run()} now stages the XML, per-sample event-count, and
aggregate report files for a sampling invocation in a private temporary
directory under \texttt{reconciliations/}.  Final outputs are published only
after every selected family and aggregate report has been generated.  If
sampling fails after one or more families have produced staged XML/count files,
the runner removes the private staging directory and preserves the previous
successful final outputs.

Successful reruns still replace gpurec-generated reconciliation artifacts and
leave manual files under \texttt{reconciliations/all/} untouched.  The publish
step temporarily backs up prior generated files and restores them if replacing
the staged files fails, while preserving the primary publish error.  CPU unit
coverage now proves that a failed rerun keeps existing XML, event-count, and
aggregate files intact and removes private staging directories.

\subsection{Checkpoint Cadence and Version Strictness}

Periodic \texttt{latest.pt} checkpoints now follow completed-step cadence:
\texttt{checkpoint\_every=2} writes after completed optimizer steps two, four,
and so on, rather than immediately after the first zero-indexed loop
iteration.  The final checkpoint still records its separate final-evaluation
row and resume cursor.

Checkpoint schema-version validation is now type-strict.  The loader accepts
only integral, non-boolean version values matching the supported schema
version, so malformed payloads such as \texttt{"1"}, \texttt{True}, or
\texttt{1.0} fail at the checkpoint boundary instead of being coerced to a
valid version.

\subsection{Workflow Batch-Packing Null Guard}

\texttt{RunConfig} now rejects an explicit \texttt{batch\_packing=null} value
from JSON-style configuration.  Omitting the field still preserves the
workflow default, \texttt{depth\_first\_fit}, while an explicit null no longer
passes through the lower-level model helper that treats \texttt{None} as the
sequential model default.

This keeps production workflow configs from silently switching resident-batch
planning policies when users include a JSON key with a null value.

\subsection{Workflow Alias Discoverability}

The \texttt{gpurec optimize} help text now documents accepted dtype,
\texttt{family\_chunk\_size}, and \texttt{batch\_packing} aliases instead of
only exposing the canonical values.  The README production workflow section
now lists the same alias families for flat JSON configs and CLI flags,
including dtype spellings, all-resident chunk-size aliases, batch-packing
aliases, and the \texttt{clade\_budget} requirement for non-sequential
packing.

A CLI help regression and a README hygiene test pin those user-facing alias
docs so accepted configuration vocabulary remains discoverable.

\subsection{CLI Subcommand Error Usage}

Post-parse CLI validation errors now report usage for the active subcommand
instead of the top-level \texttt{gpurec} parser.  The selected argparse
subparser is stored in the parsed namespace and reused for optimize, sample,
run, and backtracking validation/runtime exits, so errors such as invalid JSON
workflow config, missing optimize inputs, invalid sampling seeds, and rejected
\texttt{gpurec run --checkpoint} invocations point users at the relevant
command surface.

The CLI workflow tests now assert subcommand-specific usage for optimize,
sample, and run validation errors while continuing to require traceback-free
diagnostics.

\subsection{Optimization Cleanup Error Preservation}

\texttt{OptimizationRunner.run()} now preserves the primary optimization
failure if \texttt{model.close()} also raises during exception unwinding.
Cleanup errors are suppressed only on an already-failing path; a close failure
after a successful optimization still propagates.  This keeps the actionable
objective, checkpoint, resume, or validation error visible instead of replacing
it with a secondary cleanup failure.

A fake-model regression forces \texttt{full\_loss()} to raise and
\texttt{close()} to raise during cleanup, then verifies that the original
optimization error is the one reported and that cleanup was still attempted.

\subsection{Optimization Final Artifact Staging}

\texttt{OptimizationRunner.run()} now writes final flat artifacts into a hidden
temporary directory before publishing them into \texttt{out\_dir}.  The staged
set includes \texttt{history.jsonl} with the final-evaluation row,
\texttt{rates\_final.tsv}, optional \texttt{per\_fam\_likelihoods.tsv},
\texttt{theta\_final.pt}, \texttt{optimization\_history.csv}, and
\texttt{summary.json}.  \texttt{summary.json} is published last so consumers can
continue to treat it as the final report marker.

Before publishing, the runner backs up existing final artifacts.  If any staged
file cannot be produced or replacing a final artifact fails, old final artifacts
are preserved and private staging/backup directories are removed.  The final
\texttt{history.jsonl} row is deferred into the same publish path, so a failed
final report no longer advertises a completed \texttt{final\_eval}.  A CPU
regression injects a staged rate-table failure and verifies stale final
artifacts remain untouched.

\subsection{Shared Workflow Artifact Publication}

The sampling and optimization workflows now share their staged artifact
publication mechanics through a private workflow helper module.  Artifact
discovery stays local to each runner, but temporary directory creation,
backup/restore, staged \texttt{Path.replace()} publication, partial-output
cleanup, and primary-error preservation now live in one implementation.  This
removes the duplicated rollback code that had grown independently in
\texttt{sampling.py} and \texttt{optimize.py}.

A dedicated CPU unit module covers the shared helper directly, including nested
artifact paths, successful replacement of managed outputs, preservation of
unmanaged files, temporary-directory cleanup, and restoration of old outputs
after a mid-publish failure.

\subsection{Sampling Window Rerun Contract}

Successful sampling reruns now explicitly document and test the existing
whole-output ownership contract.  A sampling invocation may select a family
window with \texttt{family\_start}/\texttt{max\_families}, but a successful
publish still replaces the full gpurec-generated reconciliation output set in
the target directory so downstream consumers do not mix fresh window outputs
with stale outputs from an older run.  Manual files under
\texttt{reconciliations/all/} remain untouched.

\texttt{summary.json} now records the exclusive sampled family window as
\texttt{family\_start} and \texttt{family\_stop}.  The README tells users to use
a separate \texttt{--sample-out-dir} when they need to keep multiple sampled
windows.

\subsection{Strict Workflow Diagnostics JSON}

Workflow diagnostics now use a shared strict JSON serializer for JSONL history
rows and final workflow summaries.  Non-finite floating-point values are
serialized as JSON \texttt{null} instead of Python-only \texttt{NaN} or
\texttt{Infinity} tokens, while in-memory optimizer metrics remain numeric for
runtime decisions.  The same strict serializer is used for
\texttt{history.jsonl}, optimization \texttt{summary.json}, and sampling
\texttt{summary.json}; \texttt{safe\_float()} now returns \texttt{None} for
non-finite and non-numeric values.

Focused CPU tests cover non-finite tensor diagnostics flowing through the JSONL
writer and parse the result with non-standard JSON constants rejected.

\subsection{Public Validation Homogeneity}

Three public validation gaps from the API audit were closed.  Family wave
layout construction now normalizes family indices through the shared integer
validator instead of \texttt{int()}, so booleans and non-integral floats are
rejected consistently.  \texttt{theta\_init\_rates} now rejects boolean entries
and wraps tensor-conversion failures as \texttt{ValueError} messages that name
the offending option.  Uniform chunk candidate lists now reject strings and
bytes as whole values instead of treating them as character sequences.

The new CPU tests pin each edge case before any CUDA setup or input-file IO.

\subsection{CLI and Workflow Drift Guards}

The CLI/config audit found that the \texttt{RunConfig} parser surface was
already mechanically guarded, but \texttt{SamplingConfig} lacked the same
dataclass-to-parser parity check.  A new unit guard maps parser destination
aliases such as \texttt{sample\_out\_dir} and
\texttt{sample\_max\_families} back to \texttt{SamplingConfig} fields for both
\texttt{gpurec sample} and \texttt{gpurec run}.  The model-factory forwarding
test now also covers the solver tolerances and adaptive-iteration controls that
\texttt{build\_alerax\_workflow\_model()} passes into the public model
constructor.

\subsection{Strict Checkpoint Identity Metadata}

Checkpoint loading and resume compatibility now treat v1 identity metadata as
mandatory instead of optional.  A valid checkpoint must carry
\texttt{family\_names}, \texttt{species\_names}, and the configuration identity
fields used for compatibility checks: \texttt{species\_tree},
\texttt{families\_file}, \texttt{mode}, \texttt{start}, and
\texttt{max\_families}.  The family and species metadata must be string lists.

\texttt{validate\_checkpoint\_model\_compatibility()} now rejects malformed or
legacy payloads before \texttt{restore\_model\_theta()} can fall back to
shape-only compatibility.  Sampling checkpoints without family/species identity
are rejected before sampling can use model family ordering, and optimization
resume now loads checkpoints onto CPU for validation before restoring theta to
the model device.  CPU regressions cover malformed loader payloads, sampling
legacy metadata, optimization legacy metadata, and CUDA-config resume preflight.

\subsection{Public Export Surface Guards}

The top-level package now derives \texttt{\_\_all\_\_} directly from the lazy
export map, removing the duplicate public-export list.  The
\texttt{gpurec.backtracking} module now declares its own
\texttt{\_\_all\_\_}, so wildcard imports expose only the public event metadata
and sampling helper surface instead of imported dependencies and private bridge
helpers.

CPU tests now pin wildcard-import behavior for \texttt{gpurec},
\texttt{gpurec.workflow}, and \texttt{gpurec.backtracking}.  A subprocess guard
also verifies that plain \texttt{import gpurec} still avoids eagerly importing
the workflow and backtracking modules.  README hygiene tests parse fenced Python
examples and derive workflow/backtracking documentation checks from the public
export surfaces.

The installed-wheel smoke in the CPU package workflow now validates public
exports after proving the import came from site-packages or dist-packages rather
than the checkout.  It iterates \texttt{gpurec.\_\_all\_\_} and
\texttt{gpurec.workflow.\_\_all\_\_}, and checks that workflow exports resolve to
the same objects through the top-level package.  The release-readiness guide now
documents the same installed-wheel export smoke.

\subsection{Lazy Workflow Public Exports}

\texttt{gpurec.workflow} now mirrors the top-level package's lazy public-export
pattern.  A plain \texttt{import gpurec.workflow} no longer imports the workflow
configuration, optimizer, sampling, API, backtracking, or Torch modules.  Access
to \texttt{RunConfig} still loads the configuration module, but it no longer
pulls in optimizer, sampling, API, or backtracking modules.

The workflow package has a deliberate module-class guard for Python's
child-module binding behavior.  Importing \texttt{gpurec.workflow.optimize} can
bind a child module named \texttt{optimize} onto the parent package, but
\texttt{from gpurec.workflow import optimize} and
\texttt{from gpurec import optimize} continue to resolve to the public callable
regardless of import order.  Subprocess tests pin those collision cases so the
lazy import path does not become order-dependent.

The package and release-readiness installed-wheel smokes now also validate
public export discoverability through \texttt{dir()} and wildcard imports for
\texttt{gpurec.workflow}.

\subsection{Shared Workflow Checkpoint Metadata Helpers}

Checkpoint loading and optimization resume parsing now share private workflow
metadata validators.  The new helper module centralizes non-negative integer
metadata parsing, finite floating-point metadata parsing, checkpoint string-list
identity validation, and model family/species name extraction.  This removes the
parallel \texttt{\_checkpoint\_int}/\texttt{\_resume\_int} implementations while
keeping the serialized checkpoint payload and existing error contracts intact.

The refactor intentionally leaves schema-specific validation in place:
\texttt{checkpoint.py} still owns payload keys, versions, tensor checks, and
config identity checks, while \texttt{optimize.py} still owns resume-state
construction and configured-step limits.  New CPU cases cover boolean,
fractional, non-finite, and missing progress/status metadata so future changes
cannot weaken scalar validation.

\subsection{Strict Workflow JSON File Writer}

Workflow summary outputs now use a shared strict JSON file writer in
\texttt{gpurec.workflow.diagnostics}.  The helper creates parent directories,
uses the existing finite-JSON normalization, applies stable indentation and key
ordering by default, and appends the trailing newline expected by checked-in
workflow artifacts.

Both optimization and sampling summary publication now call that helper instead
of duplicating \texttt{write\_text(json\_dumps\_strict(...))}.  Focused CPU
tests cover non-finite value normalization, sorted summary keys, parent
directory creation, and the existing staged summary-output paths.  Additional
guards pin the lightweight import footprint and copy semantics of the shared
workflow metadata helpers.

\subsection{Shared Checkpoint Progress Parser}

Checkpoint loading and optimization resume parsing now share
\texttt{checkpoint\_progress()} from \texttt{gpurec.workflow.\_metadata}.  The
helper owns non-negative integer parsing for \texttt{step} and
\texttt{next\_step}, accepts integer-valued floats consistently with the other
metadata validators, and preserves the existing inconsistent-progress error
when \texttt{next\_step} is neither \texttt{step} nor \texttt{step + 1}.

The callers still own their schema boundaries: \texttt{checkpoint.py} checks the
required key set before calling the shared helper, while \texttt{optimize.py}
uses the returned \texttt{next\_step} to construct resume state and compare it
with the configured optimization step limit.  CPU tests cover direct helper
normalization, resume payload parsing, and checkpoint load rejection for invalid
progress metadata.

\subsection{Shared Checkpoint Status Metadata Helper}

Checkpoint loading and optimization resume parsing now also share
\texttt{checkpoint\_status\_dict()} from \texttt{gpurec.workflow.\_metadata}.
The helper preserves the existing contract: missing or \texttt{None} status
metadata is treated as an empty dictionary for resume defaults, while non-dict
status payloads raise the established invalid-status error.

\texttt{checkpoint.py} uses the helper as an optional-metadata validator during
load, and \texttt{optimize.py} uses the same normalized dictionary before
reading resume fields such as \texttt{best\_nll\_bits},
\texttt{best\_step}, \texttt{previous\_objective}, and
\texttt{stable\_loss\_steps}.  Focused CPU tests cover helper defaults,
invalid status values, resume defaults, and invalid resume metadata.

\subsection{Top-Level Version Metadata}

The top-level \texttt{gpurec} package now exposes \texttt{\_\_version\_\_} for
callers, notebooks, and release smoke checks that need to report the package
version without importing heavier API, workflow, backtracking, or CUDA modules.
The value comes from installed distribution metadata when available and falls
back to the source-tree project version in checkout-only usage.

A release-metadata unit guard keeps \texttt{gpurec.\_\_version\_\_} aligned with
\texttt{pyproject.toml}.  The existing subprocess import-footprint guard still
passes, so the version attribute does not weaken the lazy top-level import
boundary.
